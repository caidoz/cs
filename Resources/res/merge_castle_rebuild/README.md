# CS 성·룰렛 리소스 재제작

총 42개 PNG. 배경, 동료 CMF와 장비 아이콘은 기존 게임 리소스를 사용한다.

2026-11-10 수정: 1단계 외장과 공통 로비 버튼은 `merge_castle_original/reference.png`의 원본 픽셀로 교체했다. 나머지 성도 한 장 전체를 가로·세로 동일 배율로 그린다. 이전의 방 높이에 따른 이미지 세로 늘리기는 제거했다. 원본 비교 검증은 `verify_original.py`, 비교 화면은 `output/merge-roulette/original/comparison.html`이다.

- `chassis-01..10.png`: 성별 외장과 넓은 데크. 방 내부 5곳은 투명하며, 첨탑·기둥·공통 보를 포함한다.
- `rooms-01..10.png`: 성별 5열 × 6행 생산시설 아틀라스. 열은 시설, 행은 Lv.0~5. 총 50개 방 / 300개 강화 그림을 독립적으로 선택한다.
- `parts-01..10.png`: 6열 × 2행. 위는 포 Lv.0~5, 아래는 바퀴 Lv.0~5. 투명 배경이다.
- `ui-*.png`: 시작·이어하기·성 관리·양자택일 버튼, 메뉴, 룰렛 외장, 손잡이, 등급 발판, 유닛 상태판, 전투판, 회전용 톱니바퀴.

룰렛의 고정 외장에는 톱니바퀴가 없다. `ui-gear.png` 두 장을 축 중심에 반대 방향으로 회전시킨 뒤 외장을 겹쳐 그린다. 최초 무료 뽑기와 일반 뽑기에 모두 적용하며, 공격·대기 중에는 정지한다.

버튼 그림에는 글자를 넣지 않고 게임 폰트로 제목·설명·하트 비용을 그린다. 비활성 버튼도 불투명하게 유지한다.

원본 생성·수정 프롬프트와 원본 경로는 `generation-*.json`에 보존한다. 실제 프로젝트는 이 폴더의 PNG만 참조한다. 이미지 후처리 코드는 사용하지 않는다. `tools/merge_roulette/register_rebuild.py`는 원본 픽셀을 읽어 소스 사각형만 `Classes/Data/MergeCastleRebuild.h`에 등록한다.

게임의 기준 폭 640에서 칸은 64×64 논리 픽셀로 고정한다. 전투판은 성별로 6×4에서 8×6까지 증가하며, 외장과 방 영역이 이를 따라 커진다. 세로로 긴 화면은 위쪽 성과 기존 배경을 추가로 보여준다.

## 동작과 검증

전투 진입 시 로비 UI가 나간 뒤 전투판이 방을 덮고, 무료 3개 소환과 인벤토리 비행이 이어진다. 일반 뽑기 역시 릴 정지 → 결과 비행 → 자동 배치 순서이며, 결과는 착지 후 한 번만 반영한다. 비행 중 입력은 잠기고 추가 하트는 차감하지 않는다. 저장된 미배치 결과도 이어하기에서 같은 배치 계획으로 복원한다. 큰 결과의 자리가 부족하면 결과를 보존하며, 칸을 비웠을 때 자동 비행을 재시도한다.

스핀과 공격은 각각 하트 1개를 사용하고 깜빡임을 표시한다. 공격 후 인벤토리는 남는다. 최소 3칸이 비어 있지 않으면 스핀을 막고 안내한다.

- `test_model.cmd`: 합성·공격·저장 모델과 무작위 연산.
- `test_transition.cmd`: 50개 시설의 독립 강화·MAX·아틀라스 좌표·전환 시점.
- `verify_facilities.py`: 고유 강화 그림 300개, 실제 실행 캡처 61개, 이웃 방 4개의 픽셀 보존.
- `verify_runtime.py`: 640×850 / 640×1408, 자동 비행·입력 잠금·하트·공격 유지·빈칸 제한·이어하기·톱니 회전/감속/정지. 두 비율의 UI 좌표는 같으며, 텍스처 비교에는 GL 선형 필터링의 작은 색상 오차를 허용한다.

실제 캡처 갤러리: `output/merge-roulette/rebuild-review.html`. 기본 실행 파일: `proj.win32/Debug.win32/cs.exe`.
