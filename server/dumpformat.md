# 로컬 세이브 파일 형식 (insamdb dump)

서버가 준비될 때까지 클라이언트 안의 임시 서버가 쓰는 파일 형식이다.

목표는 하나다. **이 파일이 나중에 MariaDB로 그대로 들어가야 한다.**
그래서 형식을 새로 만들지 않고, MariaDB가 이미 읽을 줄 아는 것을 쓴다.

---

## 왜 이 형식인가

MariaDB에는 `LOAD DATA INFILE`이 있고, `mysqldump --tab`이 뱉는 것도 같은
형식이다. 그 형식은 **탭으로 나눈 텍스트**다. 그러니 우리가 그 규칙을 그대로
지키면, 이식 작업이 "파일을 테이블별로 쪼개서 `LOAD DATA` 한 줄씩 실행"으로
끝난다. 변환 코드가 없다.

반대 방향도 된다. 서버에서 `mysqldump --tab`으로 뽑은 것을 이어 붙이면
클라이언트가 읽을 수 있다. 계정 이관이나 버그 재현에 그대로 쓸 수 있다.

SQLite를 쓰지 않는 이유는 iOS·안드로이드·win32 세 곳에 빌드를 붙여야 하고,
그 대가로 얻는 것(SQL 질의)이 지금 단계에서는 별로 쓸모없기 때문이다.
어차피 임시 서버는 유저 한 명분만 다룬다.

---

## 파일 한 개, 원자적 교체

테이블마다 파일을 따로 두지 않는다. **한 파일에 전부 담는다.**

이유는 원자성이다. 저장 한 번이 `player`, `inventory`, `crew_slot`을 건드리는데
파일 세 개를 쓰다가 두 번째에서 앱이 죽으면(전화, 메모리 부족, 홈버튼)
골드는 줄었는데 아이템은 안 들어온 상태로 남는다. 진짜 서버는 트랜잭션으로
막지만 파일 세 개는 못 막는다.

파일 하나면 이렇게 하면 된다.

```
1. save.new 에 전부 쓴다
2. fflush + fsync
3. rename("save.new", "save.dat")
```

`rename()`은 같은 파일시스템 안에서 원자적이다(iOS·안드로이드 모두). 즉
`save.dat`은 항상 "이전 것 전체" 아니면 "새 것 전체"이고, 반쯤 쓰인 상태가
존재하지 않는다. 이것이 트랜잭션의 `COMMIT`에 해당한다.

## 구조

```
#insamdb    1                    <- 파일 형식 버전
#schema     1                    <- schema_version.version 과 같은 값
#user       1001                 <- account.user_id
#revision   42                   <- player.revision
#written    806349271            <- 게임 타임스탬프(초)

#table      player
#cols       user_id  revision  nickname  lv  ...
#rows       1
1001	42	폴립	7	...

#table      inventory
#cols       item_uid  user_id  item_type  detail  grade  lv  cnt  ...
#rows       17
1	1001	0	3	0	5	1	...
...

#end        3f2a91c4             <- 본문 CRC32
```

- `#`으로 시작하는 줄은 메타행이고 필드 구분은 역시 탭이다.
- **데이터 줄은 개수로 읽는다.** `#rows N` 다음의 N줄이 데이터다.
  줄 첫 글자로 판단하지 않으므로, 값 안에 `#`이 있어도 상관없다.
- 블록과 블록 사이의 빈 줄은 읽기 좋으라고 넣는 것이고 무시된다.
  데이터 구간 안에는 빈 줄이 올 수 없다(그 줄도 한 행으로 세어진다).
- 테이블 순서는 자유지만 부모가 먼저 오는 편이 낫다
  (`account` → `player` → `inventory` → `hero_equip` ...).
  외래키 때문에 import할 때 순서가 필요하다.
- 행이 0개인 테이블도 `#rows 0` 으로 적는다. "저장 안 함"과 "비어 있음"을
  구분해야 지울 것을 지울 수 있다.

### `#end`의 체크섬

`#insamdb` 줄부터 `#end` 직전까지의 CRC32다. 파일이 잘렸는지 확인용이다.
`rename()`으로 원자성을 확보했지만, 디스크가 가득 차서 write가 중간에
실패한 경우까지 잡으려면 필요하다. 안 맞으면 그 세이브는 버리고 이전
백업으로 되돌린다.

## 값 표기 규칙 (MariaDB 기본과 동일)

이 부분이 이식이 공짜가 되는 핵심이다. **직접 정한 규칙이 하나도 없다.**
전부 `LOAD DATA INFILE`의 기본 동작이다.

| | |
|---|---|
| 필드 구분 | `\t` (탭) |
| 행 구분 | `\n` (LF). CRLF 아님 |
| 이스케이프 문자 | `\` (역슬래시) |
| NULL | `\N` |
| 문자 인코딩 | UTF-8 (`utf8mb4`) |

값 안에 아래 문자가 있으면 이스케이프한다.

| 원래 문자 | 파일에 쓰는 것 |
|---|---|
| 역슬래시 | `\\` |
| 탭 | `\t` |
| 줄바꿈(LF) | `\n` |
| 캐리지리턴(CR) | `\r` |
| NUL (0x00) | `\0` |
| Ctrl-Z (0x1A) | `\Z` |

그 외:

- 정수는 10진수 그대로. 앞에 `+`를 붙이지 않는다.
- 음수는 `-` 를 붙인다.
- `TINYINT`로 쓰는 불리언은 `0` / `1`.
- 빈 문자열은 빈 필드(탭 두 개가 붙음). `\N`(NULL)과 다르다.
- `DATETIME`은 이 파일에 넣지 않는다. `created_at` / `updated_at` 같은
  운영용 컬럼은 서버가 `NOW()`로 채운다. 클라이언트가 기기 시계로 만든
  시각을 운영 지표에 섞으면 안 된다.
- 게임 로직이 쓰는 시간은 전부 `*_ts` 컬럼(BIGINT, 2000-01-01부터의 초)이고,
  이건 파일에 그대로 들어간다.

## MariaDB로 옮기기

```bash
# 1. 파일을 테이블별 .tsv로 쪼개고 LOAD DATA 문을 만든다
python server/tools/split_dump.py save.dat --out /tmp/imp

# 2. 스키마를 만들고 넣는다
mysql -u root insam < server/schema.sql
mysql -u root --local-infile=1 insam < /tmp/imp/load.sql
```

`split_dump.py`는 형식을 검증(체크섬, 행 수, 컬럼 수)하기도 하므로,
클라이언트가 쓴 파일이 규격에 맞는지 확인하는 용도로도 쓴다.

---

## 클라이언트가 지켜야 할 것

1. **컬럼 이름은 `schema.sql`과 글자까지 같아야 한다.** `#cols`가 곧
   `LOAD DATA ... (col1, col2, ...)`의 괄호 안이 된다. 순서는 달라도 되지만
   이름이 틀리면 import가 깨진다.
2. **컬럼을 빼도 된다.** `#cols`에 없는 컬럼은 스키마의 `DEFAULT`가 들어간다.
   반대로 스키마에 없는 컬럼을 적으면 import가 실패한다.
3. **`AUTO_INCREMENT` 컬럼(`inventory.item_uid`)도 값을 적는다.**
   `hero_equip.item_uid`가 그 값을 참조하므로 클라이언트가 번호를 정해야
   한다. 서버로 넘어가면 이 번호는 서버가 발급한다.
4. 저장할 때마다 파일 전체를 다시 쓴다. 부분 갱신을 하지 않는다.
   유저 한 명분이라 수 KB이고, 부분 갱신은 곧 트랜잭션을 직접 구현하는 일이다.

## 저장하지 않는 것

| | 이유 |
|---|---|
| `robin.enemyObj`의 위치·프레임 | 복원하는 `CopyEnemyObj()`가 `x/y`를 `nx/ny`로 되돌리고 `turn`·`turnPosition`·각종 `frame`을 0으로 리셋한다. 저장해도 버려진다 |
| `GAMEEVENT`의 연출 필드 | `x`, `y`, `dx`, `speed`, `zoom`, `frame`, `touchFunc` 등. 화면에서 바가 튀어나오는 애니메이션 상태다 |
| `robin.rouletteLog[1000]` 외 3개 | 선언만 있고 코드에서 한 번도 안 쓴다. 4KB를 차지하고 있었다 |
| `robin.medalShop[]` | 위와 같이 미사용. 메달 용처가 정해지면 그때 표를 만든다 |
| `ITEM.name[40]`, `ITEM.id`, `ITEM.icon` | 종류·세부·등급에서 만들어지는 값이다. 저장하면 데이터가 두 벌이 된다 |
| `CHARDATA`의 `buff` / `debuf` / `immune` | 구조체 주석에 이미 "`RefreshStat` 한 번 하면 자동 할당되거나 전투중 임시값"이라고 적혀 있다 |
