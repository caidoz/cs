# 몬스터 부위 인벤토리와 공격 및 보강 기획

작성일: 2026년 11월 16일. 대상은 룰렛 합성 턴 전투의 기본 51종과 색상 변종을 합한 357개체다. Claude와 후속 개발자는 이 문서와 `content/monster_parts/behaviors.json`을 함께 읽는다.

몬스터의 신체 부위를 공격 파츠와 수동 보강 파츠로 구분한다. 공격 파츠는 몬스터 한 턴에 각각 한 번씩 공격하며 최대 3개다. 나머지는 히어로의 장갑처럼 별도 행동을 수행하지 않고 공격 피해, 방어, 재생을 보강한다. 강한 개체의 판은 더 풍성해지지만 추가 보강 블록 때문에 공격 횟수나 대기 시간이 늘지는 않는다.

## 결정된 전투 규칙

1. 플레이어가 공격, 대포 발사, 룰렛 결과 배치로 턴을 마치면 몬스터의 공격 묶음이 시작된다.
2. 몬스터에게 지정된 공격 파츠 1개부터 3개가 순서대로 각각 한 번 공격한다. 한 턴 최대 3회다.
3. 공격 파츠 하나는 원본 CMF의 공격 모션 하나에 대응한다. 한 부위의 `hits`는 1로 고정한다.
4. 공격 보강, 방어 보강, 회복 보강 파츠는 행동 순서에 들어가지 않는다. 별도의 회복 턴이나 방어 턴을 만들지 않는다.
5. 몬스터의 기존 한 턴 피해 예산을 공격 파츠들에 나눠 배정한 후, 각 공격의 위력과 수동 보강을 적용한다. 공격 파츠마다 한 턴 전체 공격력을 다시 부여하지 않는다.
6. 회복 능력이 있는 몬스터는 공격 묶음 정산 시 소량 재생한다. 회복 보강 파츠가 재생량을 높인다. 추가 공격이나 회복 모션을 만들지 않는다.
7. 부위 파괴, 신체 탈락, 직접 조준은 후속 범위다. 현재는 몬스터 체력통 하나를 유지한다.

초기의 `엄니 → 엄니 → 대시` 순환 및 `공격 → 공격 → 회복` 순환안은 이 규칙으로 대체했다. 저장소의 현재 구현은 이 문서의 최대 3개 공격 파츠와 수동 보강 규칙을 따른다.

## 파츠 역할

| 역할 | 행동 여부 | 적용 효과 |
| --- | --- | --- |
| 핵 | 행동하지 않음 | 기존 몬스터 최대 체력 표시. 몬스터마다 하나 |
| 공격 | 파츠마다 1회, 최대 3개 | 고유한 엄니, 발톱, 돌진 등의 공격 |
| 피해 보강 | 행동하지 않음 | 공격 묶음의 피해 증가. 돌진 관통 보강 |
| 방어 보강 | 행동하지 않음 | 받는 직접 피해 감소 |
| 회복 보강 | 행동하지 않음 | 공격 묶음에 수반되는 수동 재생량 증가 |

모든 종에 다섯 역할을 채울 필요는 없다. 단단한 몬스터는 방어 보강을, 재생하는 몬스터는 회복 보강을 사용한다. 회복 보강은 늪의 주인, 슬라임, 마성의 불새, 라이트스피릿에 우선 지정했다. 색상 변종은 기본 종의 역할과 공격 구성을 공유한다.

## 멧돼지와 회복형 예시

멧돼지의 엄니와 주둥이는 `엄니 공격`, 발굽은 `대시 공격`에 대응한다. 한 턴에 엄니 공격 한 번, 대시 공격 한 번을 수행한다. 기존 CMF 패턴 1은 엄니, 패턴 0은 대시로 연결한다. 가시 가죽 그림은 현재 핵으로 사용한다. 별도의 가죽 방어 파츠를 만들 때 몸통 핵과 분리할 수 있다.

강한 멧돼지에게 엄니 그림의 보강 블록을 추가해도 그것은 수동 피해 보강이다. 직접 공격하는 엄니 무기가 추가된 것이 아니다. 판에서 붉은 공격 역할과 보라색 피해 보강 역할을 구분한다.

슬라임은 점액 공격 파츠가 공격하고, 젤 재생 부위는 수동 회복을 보강한다. 공격과 회복을 한 턴의 공격 묶음 안에서 정산한다. 회복 부위가 여러 개여도 재생은 한 번만 정산하고, 초록색 회복 숫자는 묶음이 끝날 때 표시한다.

## 강화와 부위 수

| 화면의 웨이브 번호 | 단계 | 목표 블록 수 |
| --- | --- | --- |
| 1부터 4 | 일반 | 최소 4개, 고유 부위가 5종이면 5개 |
| 5부터 9 | 정예 | 6개 |
| 10부터 15 | 강적 | 9개 |

직접 공격하는 파츠 수는 종마다 정한 1개부터 3개로 유지한다. 늘어나는 블록은 수동 보강 부위에서 선택한다. 기본 그림 중 수동 보강 부위가 없는 종은 기존 공격 부위 그림을 재사용하되, 그 추가 블록의 실제 역할은 피해 보강으로 지정한다. 이 역할 구분은 그림의 원본 종류가 아니라 런타임 블록의 역할에 저장한다.

핵은 하나만 유지한다. 색상 변종마다 동일한 부위의 원본 색상을 사용한다. 현재 강화 단계는 웨이브 기준이며, 같은 웨이브에서 체력·공격력 배율이 다른 개체는 후속 스폰 등급으로 확장한다.

```text
wave = 코드의 0부터 시작하는 웨이브 번호
성급 = min(6, 1 + floor(wave / 4) + 보스 보너스)
보스 보너스 = 15웨이브 2, 5·10웨이브 1, 그 외 0
역할 가중치 = 해당 역할 블록의 성급 합
```

부위의 비율에 따라 1×1, 2×1, 1×2를 사용하고 핵은 2×2다. 적 판은 현재 성의 유효 칸 모양을 따른다. 작은 판에서는 남은 부위가 들어갈 최소 칸을 먼저 확보하고, 공간이 부족한 블록을 1×1로 축소한다. 이 과정에서 부위를 버리지 않는다.

## 피해 예산과 수동 보강 계산

기존 체력 및 기본 공격력 곡선과 보스 배율을 유지한다. 공격 파츠 수 자체로 전체 공격력이 배수 증가하지 않도록 기존 한 턴 피해 예산부터 분할한다.

```text
B = enemyAttack × 기존 보스 배율
W = 직접 공격하는 파츠 수, 1부터 3
S = 피해 보강 역할 가중치
G = 방어 보강 역할 가중치
R = 회복 보강 역할 가중치

피해 보강률 = min(18, S)                           최대 18%
공격 위력 보너스 = min(10, floor((평균 무기 위력 - 100) / 5))
총피해 계수 = 100 + 공격 위력 보너스 + 피해 보강률
             - floor(방어 경감률 / 2) - (회복형이면 6, 아니면 0)
총피해 예산 = floor(B × 총피해 계수 / 100)
무기 피해 = floor(총피해 예산 × 해당 무기 위력 / 모든 무기 위력 합)
정수 나눗셈 나머지는 첫 무기에 배정
총 반격 피해 = 모든 무기 피해의 합
```

일반 공격 위력 100, 강한 공격 125, 돌진 150은 공격 묶음 안에서 피해를 배분하는 가중치다. 전체 예산에는 최대 10%의 위력 보너스만 반영한다. 현재 357개체×15웨이브의 총피해 계수는 기존 반격의 88~123%다. 방어형과 회복형은 생존력의 대가로 공격력이 낮다. 반격 약화 효과는 합산 피해를 기준으로 적용하고, 정수 나눗셈의 나머지를 첫 무기에 보정하여 표시된 무기 피해 합과 실제 총 피해를 맞춘다.

```text
직접 피해 경감률 = min(12, G)                      최대 12%
경감 후 피해 = 원래 피해가 0이면 0,
              그 외 max(1, floor(피해 × (100 - 경감률) / 100))

돌진 관통률 = 5 + min(10, floor(S / 2))             최대 15%
무기별 관통 피해 = floor(무기 피해 × 관통률 / 100)
방어막 흡수 = min(남은 방어막, 무기 피해 - 관통 피해)
```

방어막은 무기 순서대로 흡수한다. 돌진 외의 관통률은 0이다. 피해 경감은 기존 몬스터 방어막과 대포의 방어막 추가 피해보다 먼저 적용한다. 지속 피해에는 이번 직접 피해 경감을 적용하지 않는다.

```text
R이 0이면 수동 재생 없음
기본 재생률(bp) = 50 + min(100, R × 5)             최대 체력의 0.55~1.50%
잔여 계수 = clamp(12 - 완료한 공격 묶음 수, 0, 6)
재생률(bp) = floor(기본 재생률 × 잔여 계수 / 6)
잔여 계수가 0이면 재생 없음
재생량 = min(잃은 체력, max(1, floor(최대 체력 × 재생률 / 10000)))
```

회복 보강이 있는 몬스터만 공격 묶음을 정산할 때 재생한다. 첫 7묶음은 기본 재생률이며, 8묶음부터 감소하고 13묶음부터 소진된다. 이론상 누적 재생은 최대 체력의 14.25% 이하다(최소 1점 정수 보정 제외). 체력이 가득 차면 0, 사망했으면 0이다. 기절이나 행동 봉쇄로 공격 묶음이 생략되면 재생과 소진 횟수도 진행하지 않는다. 공격 묶음 도중 재접속해도 피해와 재생을 중복 적용하지 않는다.

### 밸런스 검증 기준

기존 지역 성장(기준 체력 330, 지역마다 ×1.17), 웨이브 체력, 5·10·15 보스 배율, 장비·동료 성장과 보상 경제를 기준선으로 사용한다. 이번 조정은 그 위에 추가된 몬스터 파츠 효과를 전체 종에 걸쳐 정규화한다. 무기 개수나 시트 조각 개수로 총피해가 곱절 증가하지 않는다.

`tools/monster_parts/test_balance.cmd`는 357개체×15웨이브=5,355개 구성을 검사하고 `output/monster-parts-balance.csv`를 출력한다. 동일 최대 체력 대비 방어·회복이 없는 적을 3/6/12턴에 잡는 일정 피해를 가했을 때 모든 종은 각각 최대 4/8/16턴 안에 처치됐다. 이는 파츠의 추가 부담을 비교하는 기준 시뮬레이션이며 실제 계정의 장비·릴 운·동료 조합을 재현한 승률은 아니다. 실제 플레이의 구간별 승률과 진행 시간에 따른 추가 조정은 필요하다.

## 모션과 판 표시

공격 파츠마다 원본 CMF 공격 모션을 한 번 연결하고, 최대 세 개를 한 묶음으로 재생한다. 수동 보강은 CMF 동작을 추가하지 않는다. 묶음의 피해와 재생은 모델에서 한 번 확정하고, 각 무기의 타격 시점에 실제 체력 피해와 방어막 흡수를 나누어 표시한다.

판에서 현재 공격 중인 파츠 하나만 강조한다. 수동 보강 파츠는 역할별 테두리와 이름표로 표시한다. 핵은 금색, 공격은 붉은색, 피해 보강은 보라색, 방어 보강은 푸른색, 회복 보강은 녹색이다.

머리글은 현재 공격 이름, 묶음의 총 피해, 직접 공격 파츠 수, 전체 부위 수를 표시한다. 부위를 누르면 공격 파츠의 개별 피해 또는 수동 보강의 합산 효과를 확인한다. 보강 블록에 공격 부위의 그림을 재사용해도 공격 파츠로 세지 않는다.

## 원본 그림과 적용 범위

CMF 원본 시트의 조각 6,192개를 확인하여 357개체용 부위 아이콘 1,295개를 만들었다. 원본 색상과 픽셀을 사용하고, 붙은 부위는 추가 크롭 또는 실루엣 마스크로 분리한다. 아리만 블랙은 시트 배치가 다른 예외라 두 부위의 추출 좌표를 별도로 지정한다.

게임에서는 아이콘을 두 개의 2048×2048 아틀라스로 묶고, 최근접 필터로 표시한다. 긴 원본은 셀 안에 들어가도록 최근접 축소한다. 개별 부위 체력, 부위 파괴, 독의 지속 피해, 신체 탈락은 이번 적용 범위에 포함하지 않는다. PVP 공성전은 기존 상대 장비 판과 전투식을 유지한다.

## 저장과 호환

룰렛 저장 버전은 12다. 몬스터 번호, 완료한 공격 묶음 수, 룰렛 결과 배치 후 반격만 받는 턴 상태를 보존한다. 기존 `counterResolved`로 피해와 재생이 이미 정산되었는지 기록한다. 이전 버전 7부터 11의 유효한 저장을 읽는다. 새 몬스터 배치는 종류와 웨이브에서 재구성한다.

## 코드와 수정 방법

| 위치 | 용도 |
| --- | --- |
| `content/monster_parts/behaviors.json` | 51종의 부위 이름, 역할, 크기, 1개부터 3개의 공격, 모션, 위력 |
| `tools/monster_parts/catalogue.py` | CMF 부위 선택, 크롭, 마스크, 시트 예외 |
| `tools/monster_parts/build_runtime.py` | 게임용 헤더와 아틀라스 생성 |
| `Classes/Data/MonsterPartsData.h` | 생성된 종별 공격과 357개체 그림 참조 |
| `Classes/MonsterPartsModel.h` | 최대 3개 무기, 수동 보강 성장, 피해 분할, 관통, 경감, 재생 |
| `Classes/MergeRouletteModel.h` | 실제 정산과 저장 및 복구 |
| `Classes/MergeMonsterAttack.inc` | 무기별 원본 모션을 한 묶음으로 재생 |
| `Classes/MergeMonsterParts.inc` | 적 판, 실제 블록 역할, 선택 설명, 현재 무기 강조 |

생성된 헤더와 아틀라스를 직접 고치지 않는다. `behaviors.json`의 공격 부위 수와 `actions` 수를 일치시키고, 모든 공격의 `hits`를 1로 둔다. 원본 추출을 바꿀 때는 행동 원본의 부위 목록도 함께 갱신한다.

```powershell
python tools/monster_parts/build_runtime.py
cmd /c tools\monster_parts\test_runtime.cmd
cmd /c tools\merge_roulette\test_model.cmd
cmd /c tools\merge_roulette\test_combat.cmd
```
