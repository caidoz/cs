# 성 메뉴 구현

로비 하단 성 버튼은 성 선택 화면을 연다. 좌우 화살표 또는 성 미리보기 영역의 가로 스와이프로 10개 성을 탐색한다. 성을 누르거나 상세보기로 들어가면 방과 파츠 메뉴가 나온다.

## 실제 규칙

- 첫 성은 기본 보유한다. 성 구매 가격은 `300 × (성 번호 + 1)` 유료화폐다. 다음 성은 직전 성의 파츠 5종이 모두 Lv.5여야 구매할 수 있다. 조건 미충족 버튼은 각 파츠 단계를 보여주며 직전 성의 업그레이드 메뉴로 연결한다.
- 구매 확인창에 가격과 구매 후 잔액을 표시한다. 구매는 출정 성을 자동 변경하지 않는다. 별도 출정 성 선택으로 변경한다.
- 방은 창고·무기고·병영·공방·지휘실 5종이다. 방은 단계당 각각 적재 +4개, 배치 +1칸, 전체 체력 +2%, 전체 방어력 +2%, 전체 공격력 +2%다. 여기서 적재량은 기존 인벤토리의 아이템 슬롯 수이며, 스택 내 수량과는 다르다.
- 파츠는 지붕·성벽·내부·대포·차대다. 전체 공격력 +1%, 전체 방어력 +2%, 전체 체력 +2%, 포 피해 +10%와 전체 공격력 +1%, 전체 능력치 +1%의 단계당 효과를 준다.
- 방/파츠 업그레이드 골드 비용은 각각 `240/300 × (성 번호 + 1) × (현재 단계 + 1)`이다. 모든 메뉴는 Lv.0부터 Lv.5까지다. 값은 `CastleMenuModel.h`에서 조정한다.
- 실제 적재량은 기존 기본값 40개와 성당 +4개에 창고 효과를 더한다. 장비 배치량은 실제 성 격자 칸 수에서 아직 올리지 않은 무기고 단계만큼 뺀다. 최대 업그레이드 시 전체 격자 칸을 사용한다. 기존 출정 점수 한도에는 무기고 단계가 추가된다.
- 드래그 배치, 출정 장비 선택, 출정 미리보기에서 배치 한도를 검사한다. 한도가 작은 성으로 선택 변경 시 초과 적재/배치/출정 점수를 먼저 정리해야 하며 아이템을 자동 삭제하지 않는다.
- 상세보기의 포 공격력은 선택 성의 공격력 효과를 적용한 영웅 피해와 포 공격 배율로 계산한 1회 기본 피해다. 실제 치명타·방어·전투 버프 적용 전 값이다. 전투력은 현재 영웅 스탯에서 성의 공격/체력/방어 효과를 바꿔 계산한 예상값으로 표시한다.
- 대포 업그레이드는 실제 포 피해에 반영하고 쿨타임을 단계당 3% 줄인다. 실제 쿨타임 게이지에도 같은 값을 사용한다. 성 선택·방·파츠 조회는 유료화폐를 차감하지 않는다.

## 저장과 기존 계정

`ROBINDATA` 마지막에 `castleProgress`를 추가하고 직렬화 목록 마지막에 붙였다. 기존 `castlePartLv`는 기존 세이브/효과 호환용으로 유지한다. 첫 변환 시 현재 성까지 보유 처리하고 지나온 성의 파츠는 완료 처리한다. 현재 성의 기존 파츠 4개는 새 파츠 단계로 옮긴다. 이후 성별 단계는 유지된다.

실제 서버/캐시 저장에는 기존 `player_flag` 표를 사용한다. `flag_kind=4`는 파츠, `5`는 방이며 `flag_idx=성번호×5+종류`다. `6`은 성 보유 여부, `7/index 0/value 1`은 새 저장 형식 표식이다. 기존 0~3 종류와 SQL 스키마를 변경하지 않는다. 구매/업그레이드/선택 시 `SaveGame()`과 기존 서버 동기화 경로를 호출한다.

## 파일과 검증

- `Classes/CastleMenuModel.h`: 구매·비용·단계·능력 효과·기존 계정 변환.
- `Classes/CastleMenuRuntime.inc`: 화면, 구매 확인, 조건 모달, 명령, 가로 스와이프.
- `tools/castles/test_castle_menu.cpp`: 구매 조건, 중복 차감 방지, 재화 부족, 단계 상한, 용량/능력 효과, 직렬화 왕복, 포 쿨타임 재정의.
- 기존 성/방/파츠 리소스와 이미지 번호를 재사용한다. 새 이미지 번호와 문자열 테이블 항목은 없다.
- 검증용 Windows 실행 파일: `proj.win32/Debug.win32/cs.castle-menu-preview.exe`. `PreviewIntDir`로 Visual Studio의 작업 중인 컴파일 디렉터리와 분리해 빌드한다.

실제 계정에서 화면 조작과 서버 저장 왕복은 별도 확인이 필요하다.
