# 성 실내 통합 리소스 V4

성 10종의 실내를 성 전체의 열린 단면으로 제작했다. 기본 상태는 하나의 연속된 이미지로 그리고, 강화한 시설만 같은 성 좌표의 해당 구역으로 교체한다. 본체의 화면 위치와 크기, 기존 파츠 조립 규격은 유지한다.

열림·닫힘 모두 같은 0단계 본체를 바탕으로 사용한다. 닫힌 상태는 기존 외벽 소재를 내부 개구부에만 합성하고, 열린 상태는 방별 강화 시설을 합성한다. 합성 영역은 공통 본체의 알파 마스크 안쪽으로 제한한다. 다른 전체 성 이미지로 교체하지 않으므로 지붕·첨탑·차대의 외곽과 위치가 바뀌지 않는다. 바퀴·대포·지휘관 발판도 같은 배치 좌표를 사용한다.

`verify_soft_sectors.ps1`은 10종의 기본/최대 강화 × 닫힘/열림 40개 화면을 수집한다. 실제 렌더링에서 본체 위치·크기, 발판, 지휘관, 포 위치의 9개 값을 닫힘→열림 사이에 비교한다.

각 시설은 기본 0단계와 강화 1~5단계를 사용한다. 마지막 성은 시설 5개를 각각 독립적으로 강화하며, 선명도를 위해 여섯 상태를 별도 이미지로 저장한다. 시설 효과와 비용, 저장 값은 기존 모델을 사용한다.

생산은 곡물·녹색 작물·청록 수조, 공방은 금속·주황 화로·청색 설계도, 식당·주점은 붉은 직물과 식탁, 문화는 청색·상아색 서가와 예배 공간, 왕실은 백금색과 화훼로 구분한다. 성의 소재에 맞춰 시설의 외장을 달리한다.

- 이미지: `Resources/res/castle_room_integrated_v4/`
- 생성 프롬프트: 같은 폴더의 `generation.json`, `effective_edits.json`, `final_castle_prompts.json`
- 생성 도구: 내장 `image_gen`. 이미지 픽셀의 후처리 없이 알파 경계를 측정해 등록했다.
- 등록 데이터: `registration.json`, `Classes/Data/CastleRoomIntegrated.h`
- 검증: `tools/castles/verify_room_upgrades.ps1` — 10종 × 6단계, 본체 크기 유지, 마지막 성의 시설별 독립 강화.

NPC의 물리 배치 배열은 `npc_floors.json`에 작성한 새 실내의 실제 바닥선에서 생성한다. 예전 `SoftCastle::Sectors`는 NPC 발판으로 사용하지 않는다. 시설 순서와 물리 구역 순서가 다른 성 5·6은 `CastleFacilities::SectorIndex`로 연결한다. NPC JSON의 `facility_index`가 기능 인덱스이며, 배열 인덱스는 물리 구역이다. `ArtRegions`는 벽 장식을 포함하는 렌더링 구역으로 NPC의 서 있는 영역과 다르다.

캐릭터 키는 성 리소스 배율과 분리했다. 같은 화면과 뷰 줌에서는 모든 성에서 지휘관 기준 높이가 일정하며, 동료는 그 절반을 고정 서기 프레임으로 정규화한다. 좁은 바닥에 들어가지 않는 인원은 추가 뒷줄을 만들어 겹쳐 세우지 않는다. 보유 데이터는 유지한다.

수정 마법 성(9번째)은 아틀라스의 두 번째 줄이 정확한 절반 높이보다 위에서 시작한다. `register_integrated_rooms.py`에서 첫 줄과 두 번째 줄의 실제 경계를 등록해 다음 성의 수정 끝을 포함하지 않도록 한다. 본체 원본의 91% 지점까지 사용해 포함된 정지 바퀴를 제외하고, 조립 높이의 93%까지 본체를 표시한다. 별도 회전 바퀴 한 줄만 남기며 시설 렌더링·NPC 발판도 같은 좌표 변환을 따른다.

Visual Studio의 소스 불일치 경고는 소스와 이전 실행 파일/PDB의 빌드 시점이 다른 경우 발생한다. 일반 Debug 실행 파일과 PDB를 함께 다시 빌드하고 `tools/castles/verify_debug_pair.py`로 GUID와 소스 SHA-256을 확인한다.
