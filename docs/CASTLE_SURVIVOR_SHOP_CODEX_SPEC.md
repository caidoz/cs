# Castle Survivor — 상점 개편 Codex 구현 기획서

버전: v1.0 / 2026-10-29  
대상: Cocos2d-x C++ 세로형 모바일 프로젝트  
상태: **기존 확정 규칙 + 구현 제안 분리**. Codex가 실제 소스 구조를 먼저 조사하고 적용한다.

## 0. 최우선 불변 규칙 (확정)
1. 성은 레벨 1~10. **성 레벨업 비용은 골드만 사용**한다. 건축 자재·정비 부품·성 확장권·격자 추가권은 만들거나 판매하지 않는다.
2. 성 레벨 상승 시 기존 설계에 따라 층 및 성 인벤토리 공간이 **자동 생성·확장**된다. 상점은 격자 크기나 칸 수를 직접 변경하지 않는다.
3. **성 메뉴**는 성 업그레이드·층 관리·내부 시설 관리·성 외형/인벤토리 확인을 담당한다. **상점 메뉴**는 구매·무료 보급·유료 패키지·재화 교환을 담당한다. 상점에서 성 레벨업 UI/액션을 중복 구현하지 않는다.
4. 로빈(검)·디아나(총)·맥스(부메랑) 3명. 기존 무기·방어구·동료·특수 아이템 데이터를 우선 재사용한다.
5. 출전 전에 영구 보유한 장비/동료는 탐험 후에도 남는다. 탐험 중 4지선다로 획득한 아이템은 탐험 종료 시 소멸한다. 영구 원본이 탐험 중 합성/사용되어도 원본 소유권은 보존한다.
6. 전투 후 보상은 **아이템 기반 4지선다**이며 일회성 버프 카드는 넣지 않는다.
7. 신규 아트 제작 없이 기존 아이콘·프레임·폰트·버튼·재화 시스템을 최대한 재사용한다. 신규 에셋이 필요하면 플레이스홀더와 필요 리소스 목록만 보고한다.
8. 가로폭/세로비 1:1.33~1:2.2에 대응. 작은 화면에서도 탭/구매 버튼 크기를 유지하고 세로 스크롤을 사용한다.

## 1. 기존 구현 조사 — 수정 전 필수
Codex는 먼저 다음을 확인하여 `docs/SHOP_IMPLEMENTATION_AUDIT.md`에 기록한다.
- 기존 상점 진입 경로, 탭, 상품 목록, 구매/보상 팝업, 골드/프리미엄 재화/에너지 관련 코드와 데이터
- 성 메뉴, 성 레벨업 비용, 자동 층/인벤토리 확장 호출 경로, 현재 저장 데이터 구조
- 장비/무기/동료 보관함, 영구/런 임시 아이템 구분, 지급 API, 중복 아이템 및 합성 정책
- 기존 인앱결제/광고/상품 식별자, 서버 검증/복원 기능 유무
- UI 좌표 체계, 클리핑/터치/스크롤, 1:1.33 대응, 현지화 텍스트/이미지
- 변경 대상 파일 목록, 삭제 금지 코드, 누락된 요구사항
**기존 코드에 없는 재화·결제 시스템을 임의로 완성된 것처럼 가정하지 않는다.**

## 2. 메뉴 정보 구조 (제안, 우선 구현 목표)
### 상점: 3탭
- **추천**: 오늘의 무료 보급, 일일 추천, 주력 상자, 스타터 상품. 반복 진열은 상품 ID 참조로 구성.
- **보급품**: 무기 보급 / 방어구 보급 / 동료 모집 / 특수 아이템 보급. 히어로별 필터(로빈·디아나·맥스) 제공. 공용 동료는 공통 표시.
- **패키지**: 골드·프리미엄 재화·탐험 에너지(기존 구현 시), 스타터/성장/동료 패키지, 광고 제거/패스(기존 시스템 확인 후 노출).
- **삭제**: 상점 내 `성열차`, `성 성장`, `건축 자재`, `정비 부품`, `인벤토리 칸 구매` 카테고리/상품/배너/버튼.
- 성 레벨업과 관련된 안내가 필요하면 구매 액션 없이 `성 메뉴에서 업그레이드` 텍스트/이동 링크만 표시. 기본 화면에는 배치하지 않아도 됨.

### 성 메뉴
- 현재 성 레벨, 다음 레벨까지 **골드 비용**, 레벨업 버튼, 자동 생성될 층/공간 미리보기(가능한 경우), 내부 시설 상태.
- 골드 부족 시 `골드 획득 방법` 안내로 상점 골드 상품 탭에 이동 가능. 상점에서 바로 성 레벨업 금지.
- 기존 성 성장·저장 데이터 변경을 최소화한다. 레벨업 성공 시 단일 트랜잭션으로 골드 차감 + 레벨 상승 + 자동 확장 + 저장.

## 4. UI 레이아웃 구현 명세
### 공통
- 상단: 닫기/뒤로, `상점`, 기존 재화 잔액 바(골드, 프리미엄 재화, 에너지 중 실제 존재하는 항목만).
- 그 아래 고정 탭 3개: 추천 / 보급품 / 패키지.
- 본문만 세로 스크롤. 탭/재화바/닫기 버튼은 고정. 좁은 비율에서는 카드가 잘리지 않고 스크롤되도록 한다.
- 디자인: 클래시로얄풍의 밝고 단순한 SD 게임 UI + 모던한 카드 레이아웃. 기존 프로젝트의 색/폰트/아이콘 우선.
- 터치 영역은 스크롤 클립과 일치해야 하며 화면 밖 카드가 터치되지 않아야 한다.
- 상품 카드: 아이콘, 상품명, 핵심 지급 내용, 구매 제한/남은 시간(있을 때), 가격 버튼, 상세 보기. 가짜 가격/확률 표시 금지.

### 추천 탭 순서
1. 오늘의 무료 보급 — 가장 먼저, 수령 여부/다음 갱신 시각 표시.
2. 추천 배너 1개 — 스타터 패키지 등 실제 사용 가능 상품.
3. 주력 상품 카드 2열 — 무기/방어구/동료/특수 아이템. 중복 데이터 생성하지 않고 보급품 탭의 동일 상품 ID 참조.
4. 필요 시 기간 한정 진열 — 미구현이면 숨김.

### 보급품 탭
- 상단 히어로 선택 필터: 로빈/디아나/맥스. 필터 선택 시 무기·방어구 풀 변경, 동료/공용 특수 아이템은 유지.
- `무기`, `방어구`, `동료`, `특수 아이템` 섹션. 모바일 2열 카드, 긴 이름은 2줄/말줄임.
- 상자 상세 팝업: 가능한 획득 대상, 등급, 확률(설정 시), 중복 처리, 영구 지급 명시.

### 패키지 탭
- 재화 묶음과 패키지 구역 구분. 실제 결제 연결된 상품만 구매 가능.
- 광고 제거/패스는 기존 시스템이 있을 때만 표시.
- 현금 상품 가격은 스토어 SDK의 현지화된 가격을 표시하고 코드에 원화 가격을 하드코딩하지 않는다.

### 상태 처리
- 로딩/빈 목록/오프라인/재화 부족/일일 수령 완료/구매 제한/결제 취소/지급 실패 각각 명확한 피드백.
- 구매 성공 시 상품 보상 내역과 보관함 이동 안내. 보관함이 가득 차도 소유 아이템을 소실시키지 않는다(기존 우편함/대기 지급 시스템 우선).
- 구매 버튼 연타/네트워크 재시도 시 중복 차감·중복 지급 방지.

## 5. 구매·지급·소유권 처리
### 구매 흐름
`상품 선택 → 구매 가능 여부/가격 검증 → 결제/재화 차감 → 지급 확정 → 영구 보관함 저장 → 결과 팝업`.
- 골드/프리미엄 재화 차감과 지급은 원자적으로 처리하거나 실패 시 보상/복구 경로를 제공.
- 현금 결제는 실제 플랫폼 구매 완료 및 검증 후 지급. 결제 취소·보류·환불 상태 처리. 클라이언트 성공 팝업만으로 지급 확정하지 않는다.
- 구매/지급에 고유 거래 ID를 사용해 멱등성 확보.
- 일일 무료 보급의 갱신 기준(서버 시각/로컬 저장)은 기존 프로젝트 방식 우선; 기기 시간 변경 악용 방지 방안 보고.

### 보유 데이터
- `catalogProductId`, `productType`, `currencyType`, `price`, `rewardRefs`, `heroFilter`, `purchaseLimit`, `resetRule`, `enabled` 등의 필드를 **기존 타입/명명 규칙에 맞춰** 매핑.
- 지급 인스턴스는 `source=SHOP`, `ownership=PERSISTENT`로 구분. 탐험 보상은 `source=RUN_REWARD`, `ownership=RUN_TEMPORARY`.
- 성 인벤토리의 칸 수는 오직 성 레벨 데이터에서 산출. 구매 보상으로 인벤토리 크기 변경 불가.
- 기존 저장 데이터의 하위 호환 및 마이그레이션 계획 수립.

## 6. 성 레벨업 처리 (상점과 연계되는 범위)
- 성 메뉴가 `castleUpgradeCostGold[level]`을 표시한다. 값은 기존 테이블을 우선 사용하며 새 비용 수치를 임의 지정하지 않는다.
- 레벨업 버튼 → 현재 레벨 < 10 확인 → 골드 충분 확인 → 골드 차감 → 레벨 +1 → 기존 자동 층 생성/인벤토리 확장 함수 호출 → 저장/화면 갱신.
- 골드 부족 시 성 메뉴에서 부족 수량 표시, 상점의 골드 상품으로 이동하는 선택적 링크만 제공.
- 상점은 성 레벨·층 수·격자 수를 변경하는 함수를 호출하지 않는다.
- 성 내부 시설 업그레이드의 별도 재화 여부는 기존 코드 우선. 새 건축 자재는 추가하지 않는다. 별도 정책이 없으면 골드만 사용하는 제안을 별도 검토 사항으로 기록한다.

## 7. 구현 단계와 작업 지시
### 1단계: 코드 감사
`docs/SHOP_IMPLEMENTATION_AUDIT.md` 생성. 기존 화면·상품·재화·성 레벨업·저장·보상 관련 코드와 수정 파일 목록 정리. 불확실한 정책은 `OPEN_QUESTIONS`로 기록.
### 2단계: 데이터·화면 개편
기존 상점 탭을 추천/보급품/패키지로 구성. 기존 카탈로그를 매핑하고 금지 상품 제거. 1:1.33/1:2.2 스크롤·터치 검증.
### 3단계: 지급 연동
구매 시 영구 아이템 지급, 재화 차감, 중복 구매 방지, 무료 보급 기록, 소유권 검증. 실제 IAP가 없으면 mock과 프로덕션 분리.
### 4단계: 성 메뉴 회귀 테스트
골드만 소비해 레벨업, 자동 층/격자 확장, 저장/재접속, 상점과 메뉴 간 이동 검증.
### 5단계: QA·문서화
변경 파일, 실제 사용 상품 ID, 미구현 결제/광고/패스, 확률 미확정 항목, 테스트 결과를 `docs/SHOP_IMPLEMENTATION_REPORT.md`에 작성.

## 8. 수용 테스트 (필수)
- [ ] 상점 탭은 추천/보급품/패키지이고 성열차 탭은 없다.
- [ ] 상점 상품에 건축 자재·정비 부품·성 확장권·인벤토리 칸 구매가 없다.
- [ ] 성 메뉴에서 성 업그레이드는 **골드만** 소비한다.
- [ ] 성 레벨업 시 기존 자동 층/인벤토리 확장이 정상 수행된다.
- [ ] 상점에서 성 레벨이나 인벤토리 칸 수를 직접 변경할 수 없다.
- [ ] 로빈·디아나·맥스 무기/장비 상품 필터가 올바른 보상 풀을 사용한다.
- [ ] 동료 모집은 실제 동료 데이터만 사용하고 임시 이름을 실데이터로 등록하지 않는다.
- [ ] 상점 지급 아이템은 탐험 종료 후에도 보유된다.
- [ ] 탐험 중 4지선다 지급 아이템은 탐험 종료 시 소멸한다.
- [ ] 재화 부족/중복 탭/구매 취소/지급 실패에서 재화나 보상이 소실되지 않는다.
- [ ] 1:1.33~1:2.2 비율에서 스크롤, 버튼, 터치 영역, 팝업이 정상 동작한다.
- [ ] 실제 IAP 미연결 상품은 실제 구매 가능한 것처럼 표시되지 않는다.

## 9. Codex에 붙여넣을 실행 지시문
```
현재 Castle Survivor Cocos2d-x C++ 프로젝트에 docs/CASTLE_SURVIVOR_SHOP_CODEX_SPEC.md를 기준으로 상점을 개편해 줘.

먼저 기존 상점, 성 메뉴, 성 업그레이드, 인벤토리 확장, 보관함, 재화/구매/저장 시스템을 조사해 docs/SHOP_IMPLEMENTATION_AUDIT.md를 작성한다.
그다음 기존 코드 구조를 최대한 재사용하여 상점을 추천/보급품/패키지 3탭으로 개편하고, 로빈·디아나·맥스 상품 필터와 영구 보관함 지급을 연동한다.

절대 지킬 규칙:
- 성 업그레이드는 성 메뉴에서 골드만 사용한다.
- 성 레벨업 시 인벤토리/층은 기존 로직으로 자동 확장된다.
- 건축 재료, 정비 부품, 성 확장권, 인벤토리 칸 판매 상품은 만들지 않는다.
- 상점에서 성 레벨업을 실행하지 않는다.
- 기존 영구 보유 아이템과 런 임시 아이템을 구분한다.
- 미구현 IAP/광고/패스는 실제 동작하는 것처럼 노출하지 않는다.
- 기존 리소스와 저장 데이터 호환성을 유지한다.

확정되지 않은 상품 가격·확률·재화명·장비 ID는 기존 데이터에서 찾고, 없으면 하드코딩하지 말고 설정값/TODO로 분리한다. 구현 후 빌드/테스트하고 docs/SHOP_IMPLEMENTATION_REPORT.md에 변경 파일과 미해결 사항을 정리한다.
```

## 10. 아직 결정되지 않은 정책
1. 상자 확률, 천장/보장 시스템, 중복 보상 처리.
2. 프리미엄 재화 이름 및 실제 존재 여부, 상품 가격, 무료 보급 갱신 시각.
3. 무기/방어구 상자의 선택 히어로 고정 여부 또는 3히어로별 별도 상품 운영.
4. 장비 강화 비용과 성 내부 시설 비용(성 레벨업 자체는 골드만 확정).
5. 광고 제거/패스/탐험 에너지의 실제 구현 및 노출 범위.
6. 성 레벨별 자동 층 생성 및 인벤토리 크기의 구체 테이블(기존 코드 기준).

**Codex는 위 미정 정책을 독단적으로 확정하거나 새로운 유료 상품을 추가하지 않는다.**
