# 전투신 인벤토리 표현 기획서

> 전투 중에 가방(백팩 그리드)을 어디에, 어떻게 보여 줄 것인가.
> 목표 두 가지 — **박진감**(전장이 커 보이고 타격이 묵직할 것)과
> **수치 가독성**(무엇이 언제 얼마를 때리는지 읽힐 것).

작성일 2026-11-03 · 대상 빌드 `feature/bag-game`

---

## 1. 지금 무슨 일이 일어나는가

전투 시작을 누르면 **가방이 화면 아래로 통째로 사라집니다.**

```c
// Func_Draw.cpp
#define STAGE_UI_DROP_RATE 0.60f        // 화면 높이의 60% 만큼 내려간다
static bool StageUiHidden(void) {
    return IsStageRealtime() && gStageCombatStarted && !GridTestOfferOpen();
}
```

내려간 만큼 전장이 아래로 자랍니다(`GetStageInventoryTop` → `GetStageSceneGroundY`).
즉 현재 설계는 **"싸울 때는 전장, 고를 때는 가방"** 으로 화면을 통째로 갈아 끼웁니다.

### 그래서 생긴 문제

| | 현상 |
| :--- | :--- |
| **수치가 사라진다** | 칸마다 도는 쿨타임(`GridDrawCharge`)과 번쩍임(`STAGE_SWORD_FLASH`)이 **화면 밖에서** 돈다. 무엇이 찼고 무엇이 쉬는지 알 수 없다. |
| **인과가 끊긴다** | 탄은 날아오는데 그게 **어느 칸에서 나온 것인지** 보이지 않는다. 가방을 짠 보람이 전투에서 확인되지 않는다. |
| **피드백 지연** | 배치를 바꿔도 그 결과를 **다음 정비 화면까지** 기다려야 안다. |

박진감 쪽은 재료가 이미 있습니다 — `hitStopFrame`(히트스톱), `effect.shake`,
`SetDmgNum`(피해 숫자), 검 공전(`StageOrbitDraw`), 협공 연출(`stageHeroUltTitle`).
**쓰이고 있으나 서로 묶여 있지 않습니다.**

## 2. 다섯 갈래

### (가) 지금 그대로 — 전투 중 완전 숨김

* **얻는 것**: 전장이 가장 크다. 연출이 화면을 다 쓴다.
* **잃는 것**: 수치 전부. 가방 전략이 "들어가기 전의 일" 로 격하된다.
* **평가**: 박진감 100 / 수치 0. 지금 상태.

### (나) 축약 띠 (Compact Strip) — **권장**

격자를 **한 줄 아이콘 띠**로 줄여 화면 맨 아래에 남깁니다.
칸의 모양·배치는 버리고 **쿨타임 게이지와 아이콘만** 남깁니다.

```
┌───────────────────────────────────────────┐
│                                           │
│              전  장  (크게)                │
│                                           │
├───────────────────────────────────────────┤
│ ▓▓▓░ ▓▓▓▓ ▓░░░ ▓▓░░ ▓▓▓▓ ░░░░  ← 쿨 게이지 │
│ 검   포   동료  갑옷  검   동료            │
└───────────────────────────────────────────┘
```

* **얻는 것**: 전장을 거의 다 쓰면서 "지금 무엇이 차 있나" 가 한눈에.
  띠 높이는 `GRIDTEST_HUDH(20 × _2X)` 한 줄이면 충분하다.
* **잃는 것**: 배치(인접 시너지)는 안 보인다 — 다만 **전투 중에 배치를 바꾸지는
  않으므로** 잃는 것이 적다.
* **구현 지점**: `StageUiHidden()` 이 참일 때 격자 대신 띠를 그린다.
  띠의 재료는 이미 있다 — `GridTestSwords` / `GridTestShields` / `StageFoeGearList`
  가 쓰는 `StageSword` 목록과 `GridDrawCharge`.

### (다) 반투명 오버레이

격자를 제자리에 두되 알파를 낮춰 전장 위에 겹칩니다.

* **얻는 것**: 배치까지 그대로 보인다. 구현이 가장 짧다(알파 한 줄).
* **잃는 것**: **전장이 작아지지 않는 대신 가려진다.** 세로 화면에서 가방이
  화면의 3분의 1을 먹으므로, 적이 그 뒤에 숨는다. 반투명은 "둘 다 안 보이는"
  쪽으로 가기 쉽다.
* **평가**: 가장 싸지만 박진감을 가장 많이 깎는다.

### (라) 디에게틱 — 성 위에 싣는다

칸을 UI 가 아니라 **성채의 적재함**으로 그립니다. 성 그림 위에 짐처럼 얹고,
쿨타임이 차면 그 짐이 빛납니다.

* **얻는 것**: 화면에서 UI 영역이 사라진다. 박진감이 가장 높다.
  기획 철학(§2 "가방 = 성 내부 적재함")과도 정확히 맞는다.
* **잃는 것**: **칸이 너무 작다.** 성은 화면 폭의 55%(`kStarterViewportRatio`)인데
  거기에 12×4 격자를 얹으면 한 칸이 6px 아래로 떨어진다. 수치는 읽을 수 없다.
* **평가**: 그림은 최고, 수치는 최악. **(나)와 섞어** 성 위에는 빛만, 수치는
  띠에서 — 이 조합은 쓸 만하다.

### (마) 타격-칸 연결 (어느 안과도 함께)

**이것은 배치 문제가 아니라 "연결" 문제입니다.** 어느 안을 고르든 같이 해야 합니다.

1. **색으로 잇는다** — 칸마다 고유색을 주고, 그 칸이 쏜 탄과 그 탄이 낸 피해
   숫자를 같은 색으로 칠한다. 지금은 스킬 차수로만 색이 갈린다
   (`pvpClashActorLevel` 기준 노랑/파랑/분홍).
2. **궤적을 남긴다** — 칸 → 표적까지 한 프레임짜리 선. 격돌(PVP)은 이미
   칸에서 탄이 나간다. 스테이지는 검이 공전 자리에서 나간다
   (`StageOrbitPos`) — 그 자리와 띠의 칸을 잇는다.
3. **되울린다** — 피해가 들어간 순간 그 칸을 한 번 더 번쩍인다. 지금 번쩍임은
   **쏠 때** 한 번뿐이라, 맞았는지 빗나갔는지가 칸에 안 돌아온다.

## 3. 권장안 — (나) + (마), 선택적으로 (라)

**축약 띠로 수치를 남기고, 색과 궤적으로 칸과 타격을 잇는다.**

이유 셋.

1. **전장을 안 줄인다.** 띠는 한 줄이다. 지금 60% 내려가던 자리를 거의 그대로
   전장이 쓴다.
2. **버리는 정보가 가장 싸다.** 전투 중에 배치를 바꾸지 않으므로 "모양"은
   그 시간 동안 쓸모가 없다. 반면 "쿨타임"은 매 순간 바뀐다 — 남겨야 할 것은
   이쪽이다.
3. **이미 있는 것을 잇는 일이다.** 새로 그릴 그림이 없다. 목록 함수도,
   게이지 함수도, 히트스톱도 다 있다.

### 단계

| 단계 | 할 일 | 건드리는 곳 |
| :---: | :--- | :--- |
| 1 | 전투 중 축약 띠 — 아이콘 + 쿨 게이지 한 줄 | `Func_Draw.cpp` 격자 그리기 분기 |
| 2 | 칸 고유색 → 탄·피해 숫자에 같은 색 | `StageFoeShotFireFrom`, `SetDmgNum` |
| 3 | 명중 시 칸 되울림(두 번째 번쩍임) | `StageFoeShotHit` |
| 4 | 큰 한 방에만 히트스톱·셰이크 — 지금은 협공에만 걸려 있다 | `Func_Combat.cpp` |
| 5 | (선택) 성 위 짐 빛내기 — 디에게틱 보강 | `BattleMobileCastle.h` |

### 새로 둘 값

```c
//---- 전투 중 축약 띠 ----
#define STAGE_STRIP_H        (22 * _2X)  //띠 높이. 한 줄이면 족하다
#define STAGE_STRIP_CELL     (18 * _2X)  //아이콘 한 칸
#define STAGE_STRIP_MAX      12          //넘으면 쿨이 급한 순으로 자른다
#define STAGE_HIT_FLASH      (FPS / 6)   //명중 되울림 길이
```

## 4. 결정이 필요한 것

1. **띠에 무엇까지 싣는가** — 치는 것(검·포·동료)만인가, 안 치는 방어구까지인가.
   *제안*: 치는 것만. 방어구는 쿨이 없어 게이지가 빈 칸으로 남는다.
2. **칸이 12개를 넘으면** — 자를 것인가, 줄여 넣을 것인가.
   *제안*: 쿨이 급한 순으로 12개. 나머지는 "+3" 으로 적는다.
3. **접기 버튼을 남기는가** — 띠마저 치우고 순수 전장을 보고 싶을 때.
   *제안*: 남긴다. 지금 `STAGE_UI_DROP_RATE` 경로를 띠에도 그대로 쓴다.
4. **(라) 디에게틱을 할 것인가** — 그림은 좋지만 칸이 6px 아래로 떨어진다.
   *제안*: 수치는 띠에 두고, 성 위에는 **쏘는 순간 빛만** 얹는다.

---

## 5. 하지 말아야 할 것

* **반투명으로 덮지 않는다.** 가방과 전장이 같은 자리를 다투면 둘 다 안 읽힌다.
* **수치를 두 군데에 적지 않는다.** 띠와 성 위에 같은 숫자가 있으면 어느 쪽이
  진짜인지 눈이 묻는다. 숫자는 띠, 빛은 성.
* **히트스톱을 잔타에 걸지 않는다.** 검 여럿이 제 시계로 치는 구조라
  (`stageSwordCool`), 매 타격에 멈추면 게임이 끊긴다. **협공·궁극기·치명타**
  같은 드문 한 방에만.
