## 0. 수치의 두 갈래

섞으면 한쪽이 다른 쪽을 삼킨다. 새 수치를 더할 때 먼저 어느 갈래인지 정한다.

| 갈래 | 무엇이 | 곱하는 것 | 왜 |
| :--- | :--- | :--- | :--- |
| **크기값** | 방어막, 최대 체력 | `price × (등급+1) × 레벨` | 장비가 좋아지면 통째로 커져야 하는 양 |
| **비율값** | 공격력%, 치명타, 쿨감, 회피, 흡혈, 재생, 골드 | `(등급+1) × 레벨` **만** | `price` 를 곱하면 장비 하나로 상한을 넘는다 |

표의 모든 비율값은 **1/10 % 자리**로 적는다(`25` = 2.5%). 크기값도 1/10 자리다.
(`Classes/Data/GearRoleData.h`)

## 1. 장비 → 히어로 환산

가방에 오른 장비 하나가 주는 양. 모든 장비를 훑어 더한다.

`price` 는 **그 장비가 얼마나 큰가**다. 금화 값이 아니다.

| 어디서 온 장비 | price |
| :--- | :--- |
| 판 안 상점 | `kShopPart` 의 값 (4 ~ 60) |
| **창고** | `min(40, 4 + 부위 안 번호 × 2)` — `GEAR_UNIT_*` |

창고 장비는 전에 **0** 이었다. 그래서 아래 식의 `: 8` 로 떨어져 **나무칼이든
엑스칼리버든 똑같은 크기**로 쳐졌다. 아이템 표의 금화 값(`itemPrice`, 200~10만)은
상점 값과 자가 달라 그대로 못 쓰므로, **부위 안의 번호**를 단계로 쓴다.

```
step = (등급 + 1) × max(1, 겹친 레벨)
unit = (price > 0 ? price : 8) × step

gems   = 상하좌우로 맞닿은 보석 수
ampPct = 100 + gems × 25          // 주 역할이 가리키는 수치에만 건다

방어막      += unit × defPer × (주역할==방어 ? ampPct : 100) / 1000
최대 체력   += unit × hpPer  × (주역할==보조 ? ampPct : 100) / 1000

공격력%     += atkPct      × step × (주역할==공격 ? ampPct : 100) / 1000
치명타%     += critPct     × step × (주역할==공격 ? ampPct : 100) / 1000
쿨감%       += coolPct     × step / 10        // 증폭 없음
회피%       += dodgePct    × step / 10        // 증폭 없음
흡혈%       += leechPct    × step × (주역할==회복 ? ampPct : 100) / 1000
체력재생    += hpRegen     × step × (주역할==회복 ? ampPct : 100) / 100   // 1/10점/초
방어막재생  += shieldRegen × step × (주역할==회복 ? ampPct : 100) / 100   // 1/10점/초
골드        += gold        × step                                        // 1/10원
```

**합계 상한** — 마지막에 한 번 자른다. 표에는 상한을 적지 않는다.

| 공격력 | 치명타 | 쿨감 | 회피 | 흡혈 |
| :---: | :---: | :---: | :---: | :---: |
| 150% | 50% | 40% | 30% | 20% |

보석(`GEAR_LINE_SOCKET`)은 제 수치가 없어 합계에서 빠진다 — **맞닿은 이웃만 불린다.**
(`GridQueryGearRoles`, `Func_Draw.cpp`)

### 부위별 계수

주/부 역할과 계수는 `kGearRole[]` 한 곳에 있다. 한 줄이 한 부위·한 히어로다.

| 부위 | 로빈 | 다이애나 | 맥스 |
| :--- | :--- | :--- | :--- |
| 무기 | 검 치명 1.0, 흡혈 1.0 | 총 치명 1.5, 쿨감 1.0 | 부메랑 치명 0.5, 쿨감 10.0 |
| 머리 | 투구 방어 2.5/price, 치명 1.0 | 모자 쿨감 15.0, 치명 1.5 | 캡 쿨감 10.0, 방어 1.2 |
| 몸통 | 갑옷 방어 4.0 | 조끼 방어 2.5, 체력 8.0 | 코트 방어 2.0, 막재생 0.5 |
| 손 | 건틀릿 공격 3.0%, 방어 1.0 | 암릿 공격 2.0%, 쿨감 2.0 | 글러브 공격 1.5%, 흡혈 1.0 |
| 하체 | 킬트 체력 18.0, 체재생 0.4 | 치마 체력 12.0, 회피 1.0, 치명 1.0 | 바지 체력 25.0, 방어 1.0 |
| 발 | 그리브 방어 2.0, 막재생 0.4, 골드 1.0 | 신발 회피 1.5, 체재생 0.3, 골드 1.0 | 부츠 막재생 0.8, 방어 1.0, 골드 2.0 |
| 공용 | 방패 방어 3.0, 막재생 0.6 · 목걸이 체력 5.0, 체재생 0.8 · 반지 공격 1.0%, 치명 2.0, 흡혈 0.5 | | |

## 2. 히어로 2단 게이지

```
방어막 =  max(100, (100 + 히어로 ARMOR × 3) + 장비 방어막 합
                   + min(그 합 × 20%, 성 방어파츠 × 20))

체력   = (히어로 HP + 장비 최대체력 합) × (100 + min(20, 성 체력파츠%)) / 100
```

성의 몫은 **양쪽 다 20% 상한**이다. 동료는 체력을 1도 보태지 않는다.
체력이 0이면 **즉시 판 종료**(부활·성 자동방어 없음).
(`StageUpdateFortressDefense` · `StageInitFortressHealthAndArmor`, `Func_Battle.cpp`)

## 3. 피해 계산

### 3-1. 기본 피해

곱하는 차례가 곧 식이다. 순서를 바꾸면 값이 달라진다.

```
dmg = 공격력 × dmgPct / 100
    × (100 + 추가타%) / 100            // 회전력 상승
    × (200 + 치명피해%) / 100          // 치명타일 때만
    × 방어 감소
    × 속성 저항
    × (저주면 75%)
    × 무기 진폭                        // 최소~최대 사이
```

**방어 감소** — 레벨 차이로 정한다. 둘 다 120에서 끊는다.

```
감소 후 비율 = 25 + max(0, 75 - (맞는쪽Lv × 36 × 75) / (때리는쪽Lv × (144 - 때리는쪽Lv)))
```

최대 75%까지만 깎인다(바닥 25%). **속성 저항**도 같은 75% 바닥이다.
(`CalcBaseDamage`, `Func_Combat.cpp`)

### 3-2. 방어막이 먼저 닳는다

```
흡수 = min(피해, 방어막)
방어막 -= 흡수
피해   -= 흡수
남은 피해만 체력을 깎는다
```

**누구 것이든 같은 규칙**이다 — 히어로도 몬스터도. 한쪽만 2단이면 나란히 선 체력창
둘이 서로 다른 것을 재게 된다. 제 방어막을 따로 굴리는 보스(매머드 등)는 앞 가지에서
갈라져 여기 오지 않는다. (`Func_Combat.cpp`)

## 4. 공격 주기

### 4-1. 가방의 검

```
쿨타임(프레임) = FPS/2 + 칸 길이 × FPS/6
```

긴 검일수록 느리다. 검은 **각자 제 시계**로 돈다 — 서로를 기다리지 않는다.

### 4-2. 히어로 본체

```
haste = min(80, 장착무기 보정 + 장비 쿨감%)
쿨타임 = max(1, 검 쿨타임 × (100 - haste) / 100)
```

장착무기 보정은 **그 검에 투구가 맞닿아 있으면 15**, 아니면 0이다.
부메랑은 고정 `STAGE_MAX_BASIC_COOLDOWN`, 검이 아니면 `FPS`.
(`StageHeroCooldown` · `StageSwordCooldown`, `Func_Battle.cpp`)

### 4-3. 방어막 충전

| 무엇 | 주기 |
| :--- | :---: |
| 방패 | 150f (2.5초) |
| 갑옷·조끼·코트 | 210f (3.5초) |
| 그 밖의 방어구 | 240f (4.0초) |

충전량:

```
base = (price > 0 ? price × 3 : 25)
갑옷 계열이면 base × 1.5
갑옷 계열이면 base += base × 15% × (맞닿은 방어구 수)
값 = max(15, base × (등급+1) × max(1, 레벨))
```

(`StageShieldCooldown` · `GridTestShields`)

### 4-4. 동료

```
쿨타임 = 올림(attackMs × FPS / 1000)      // AllyBalanceData.h 의 Profile
피해   = 기준 × attackPercent / 100
```

64명이 각자 `attackMs` 2400~4800ms, `attackPercent` 75~120 을 갖는다.
표가 없으면 `BOSSRAID_CREW_COOLDOWN` 으로 돈다. (`BossRaidCrewCooldown`)

## 5. 성 대포 — 보조 화력

```
포 피해 = 히어로 공격력 × 대포등급계수% / 100 × 60 / 100 + 검 시너지 보너스
```

`STAGE_CANNON_SUPPORT_PCT = 60`. 지분 목표는 **히어로 60% · 동료 20% · 대포 20%** 이고,
**대포 없이도 전 웨이브가 클리어 가능**해야 한다.

맞닿은 정수에 따라 디버프가 붙는다 — 불 → 중독 180f, 얼음 → 둔화 180f, 번개 → 기절 30f.
(`ArtilleryHit`, `CastleArtilleryRuntime.inc`)

## 6. 적 체력 곡선

**등비**다. 무기 한 자루(`WAVE_STAGE_PER_TIER` 스테이지)마다 한 계단.

```
계단값(t) = 330 × 1.17^t           // 정수 곱셈 반복, pow() 안 씀
계단 안   = lo + (hi - lo) × (스테이지 % 계단크기) / 계단크기
최종      = 계단 안 × (100 + 몬스터 ADDHP) / 100 × 보스배수 × 시연배수
```

- 시작 **330** — 첫 검 10, 실제 타격은 그 3배쯤이니 "보통 공격 열 대".
- 비율 **1.17** — 35자루를 모으며 얻는 배수 ≈ 270, `270^(1/35) = 1.174`.
  **이보다 빠르면 장비를 껴도 영영 뒤처지고, 느리면 후반이 무의미해진다.**
- 계단 상한 **120** (60,000 스테이지).

**보스 배수** — 소보스 ×5, 중보스 ×10, 대보스 ×100. 고정값이 아니라 배수인 이유는,
잡몹 체력이 이미 곡선을 따라 오르므로 **어느 구간에서든 "잡몹 몇 마리분"** 이라는
감각이 같아야 하기 때문이다. (`GetWaveHp` · `GetWaveHpTier`, `Func_Map.cpp`)

### 보스는 커 보인다

체력 배수와 짝이다. 자리가 세질수록 덩치도 같이 커야 **체력바를 읽기 전에**
보스인 줄 안다. (`GetWaveSizePct`)

| 자리 | 체력 | 크기 | 색 |
| :--- | ---: | ---: | :--- |
| 잡몹 | ×1 | ×1.0 | 그 바퀴의 색 |
| 소보스 | ×5 | ×1.2 | 그 바퀴의 색 |
| 중보스 | ×10 | ×1.45 | **한 단 위** |
| 대보스 | ×100 | ×1.8 | **두 단 위** |

1.8 이 상한인 것은 그 이상이면 머리가 화면 밖으로 나가서다.

### 판 · 지역 · 바퀴

```
15 웨이브 = 1 판      (STAGE_MONSTER_CNT)
10 판     = 1 지역    (STAGE_PER_CYCLE) → 끝에 그 지역의 배경 보스
15 지역   = 1 바퀴    (STAGEBG_REGION_CNT) = 150 판
 7 색     = 전체      (STAGEBG_CYCLE_COLOR_CNT) = 1,050 판
```

보스 자리는 판 안에서 **5 · 10 · 15** 번째다 — 로비 상단 띠의 깃발 세 개와 같은
자리다. 대보스는 **150 웨이브마다**, 곧 지역의 끝이다(`content/wave_rule.tsv`).

배경 그림은 열다섯 장뿐이라 150 판이면 바닥난다. **바퀴가 넘어가면 배경에 그
바퀴의 색을 입힌다**(`StageBg::CycleTint`) — 몬스터 색과 같은 축이다. 같은 땅,
더 독한 계절.

### 적의 방어막

```
방어막 = max(60, 60 + 적 ARMOR × 3)
```

히어로와 같은 2단 구조를 적에게도 준다. (`STAGE_FOE_ARMOR*`)

## 7. 가방의 두 한도

**둘 다 격자에서 나온다.** 전에는 점수가 고정 상수라 "칸은 비었는데 못 싣는" 일이 있었다.

```
쓸 수 있는 칸 = max(1, 보이는 칸 - (5 - 방 업그레이드 레벨))
출정 점수     = max(10, 쓸 수 있는 칸) + 성파츠 + 방 레벨
드는 점수     = max(1, 차지하는 칸)
```

**한 점이 한 칸이다.** 전에는 칸 둘에 한 점이었는데 **올림**이라 1칸짜리도 1점을
물었다 — 1칸 장비 여덟이 여덟 칸을 쓰면서 여덟 점을 무는데 예산은 칸의 절반이었다.
**격자는 텅 빈 채로 점수만 떨어져** 뒤에 오는 것이 통째로 퇴짜를 맞았다.
갑옷을 1×1로 확정하면서 1칸 장비가 많아져 이 어긋남이 커졌다. 이제 관문은 하나다.

방을 한 번도 안 올리면 **보이는 것보다 5칸 적게** 쓴다.
(`CastleMenuModel::Equipment` · `LoadoutPoint` · `LoadoutCost`)

### 칸 모양

**`GridGearPart` 한 곳**에서만 나온다 — 창고에 그려지는 크기가 곧 확정 크기다.

| 무엇 | 칸 |
| :--- | :--- |
| 검·총 | 1×2 (detail<10) · 1×3 (<25) · 1×4 |
| 부메랑 | 1×2, detail≥10 이면 2×2 |
| 대포 | 성·등급마다 2×2 ~ 3×2 (그림이 들고 있다) |
| **그 밖 전부** | **1×1** — 갑옷도 동료도 여기 |

## 8. 스테이지 보상

### 영구 골드 — 잡은 놈의 체력이 곧 보상이다

```
골드 = (20 + 그놈의 최대 체력 / 25) × (100 + 깃발%) / 100
```

전에는 `20 × (판 + 1)` 이었다. 판에 **비례**해서 오르는데 몬스터 체력은 **등비**로
오른다(§6). 속도가 달라서 깊이 갈수록 **"열 배 단단한 놈을 잡고 받는 돈은 두 배"**
가 됐다. 그리고 자리(소·중·대보스)가 보상에 **전혀 안 나타났다** — 백 배 체력을
깎고도 잡몹과 같은 돈이었다.

체력으로 주면 **체력 곡선이 곧 보상 곡선**이라 둘이 영영 안 어긋나고, 보스
배수(§6)가 그대로 보상 배수가 된다.

| 자리 | 체력(첫 판) | 보상 |
| :--- | ---: | ---: |
| 잡몹 | 330 | 33 |
| 소보스 | 1,650 | 86 |
| 중보스 | 3,300 | 152 |
| **대보스** | 33,000 | **1,340** |

`STAGE_KILL_GOLD_HP_DIV` 가 전체 보상의 손잡이다. 올리면 전부 내려간다.
(`VanishMove`, `Func_Movement.cpp`)

### 판 안 골드 — 평평하다

```
시작 10
처치당 +5  (+2 신발을 바닥 열에 두면, + 보조 역할축의 골드 합)
```

상점 값(`kShopPart`, 4~60)이 **영원히 고정**이라 이 경제는 의도적으로 평평하다.
판이 올라도 한 판 안에서 쓸 수 있는 돈은 같다 — 세지는 것은 장비이지 예산이 아니다.
**창고는 영구, 가방은 한 판**이라는 구분이 여기서 갈린다.
(`GridTestBeginOffer`)

### 상자

판의 **마지막 몬스터**에서만 떨어진다. 그게 "이번 판이 끝났다" 의 유일한 신호라
중간에 또 떨어뜨리지 않는다. 판 전투 중 날아다니는 것은 이 상자뿐이다 —
처치 골드는 동전을 만들지 않고 바로 들어간다.

## 9. 성 경제

```
업그레이드 비용 = (방이면 240, 파츠면 300) × (성번호+1) × (현재레벨+1)
유료 비용       = 올림(위 값 / 100)
최대 레벨       = 5, 분류 5가지
창고 칸         = base + 성번호 × per + 방레벨[0] × 4   (상한 있음)
```

**성 구조 점수** (전투력 표시용, 피해가 아니다):

```
점수 = (성번호+1) × 1000 + 쓸수있는칸 × 25
     + Σ (성번호+1) × (파츠레벨 × 100 + 방레벨 × 80)
```

(`CastleMenuModel.h`)

## 12. 아직 식이 아닌 것

고치기 전에 알고 있어야 하는 자리다.

- **`LOADOUT_CELL_PER_POINT`** — 한 점이 한 칸이 되면서 아무도 안 쓴다. 지울 것.
  (`LOADOUT_DEBUG_BONUS` 는 걷어냈다 — 디버그와 정식의 밸런스가 갈리면 지금 보고
  있는 것이 무엇인지 알 수 없다.)
- **`STAGE_FOE_ARMOR`** — CLAUDE.md §3에 없는 축이다. 적에게 2단 게이지를 주면
  전투가 길어진다. 유지할지 정해야 한다.
- **`WAVE_HP_TEST_MUL`** — 시연용 배수(평소 1). 곡선은 그대로 두고 전체를 올린다.
- **동료 `power` · `synergy[]`** — `AllyBalanceData.h` 에 값은 다 있는데, 실시간
  스테이지에서 쓰는 것은 `attackMs` 와 `attackPercent` 둘뿐이다.
