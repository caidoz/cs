## 0. 한눈에

```
   [열 A] [열 B] [열 C]              ┌ 적 (체력이 곧 난이도) ┐
 ┌──────┬──────┬──────┐
 │ 세바 │ 로키 │ 엘사 │  ← 행 0      히어로 ──▶ 적 ◀── 동료 카드
 ├──────┼──────┼──────┤
 │ 세바 │ 세바 │ 꼬마 │  ← 행 1  ★ 가로 한 줄 = 세바스찬 3단 스킬(히어로 궁극기)
 ├──────┼──────┼──────┤
 │ 알마 │ 엘사 │ 로키 │  ← 행 2
 └──────┴──────┴──────┘
   [돌리기 A] [B] [C] [전부]     베팅 ×1 ×2 ×3 ×5 ×10 ×30 ×100
```

* **판**: 3열 × 3행 = 9칸. 각 칸에 동료 카드 한 장.
* **줄**: 가로 3 + 세로 3 + 대각 2 = **8줄**. 한 줄에 같은 동료 3장 = **3단 스킬 (한방)**.
* **내 행동**: 매 턴 **열 하나를 골라 돌린다** (그 열 3장이 떨어져 나가고 새 3장이 위에서 떨어진다). 전부 돌리기도 된다.
* **안 터진 카드는 그 자리에 남는다.** 그래서 "다음 수" 가 보인다. 세바스찬 둘이 행 1 에 있으면 열 C 만 돌리면 된다.
* **베팅은 피해에도 곱해진다** (지금 `betMul` 그대로). 판이 깔렸을 때 베팅을 올려 돌리는 것이 "한방" 이다.
* **난이도 = 적 체력**. 성 하나 = 웨이브 10개, 10번째가 보스. 보스를 죽이면 성 클리어.

## 2. 판과 덱

### 2-1. 판 (3×3)

* 9칸. 모든 칸에 카드가 있다. 빈칸은 없다 (빈칸이 있으면 "무엇을 세야 하나" 가 생겨 읽기가 흐려진다).
* 줄 8개. 같은 줄에 **같은 동료** 가 몇 장인지만 센다.

| 줄 안 같은 동료 수 | 발동 | 피해 |
| :---: | :--- | :--- |
| 3 | **3단 스킬** (히어로 궁극기 또는 소환). 줄 전체가 소멸하고 새 카드가 떨어진다 | 궁극기 본래 값 × 베팅 |
| 2 | 2단 스킬. 두 장이 소멸 | 300% × 베팅 |
| 1 (줄이 안 됨) | 1단 스킬. **소멸하지 않고 남는다** | 100% × 베팅 |

* 한 카드가 여러 줄에 걸치면 **가장 높은 단계 하나만** 발동한다. 센터 칸(1,1)은 4줄에 걸쳐 가장 가치가 높다 — 3매치의 "가운데" 와 같은 감각.
* 1단 공격은 **돌린 열의 카드만** 쏜다. 돌리지 않은 열의 카드는 서 있기만 한다. (안 그러면 "아무 열이나 돌려도 9장이 전부 쏨" 이 되어 열을 고를 이유가 없다.)

### 2-2. 덱 (런 동안 자라는 동료 뭉치)

* 런 시작 덱 = **편성 6명 각 1장**. 6명이 안 되면 그 수만큼.
* 새 카드는 **덱에서 복원 추출**한다. 칸마다 독립. 즉 **확률 = 그 동료 장수 / 덱 장수** 이고, 이 분수를 화면에 그대로 적는다 ("세바스찬 3/9").
* 덱은 **LBaL 식으로 자란다**: 적을 하나 죽일 때마다 **동료 카드 3장 중 1장** 을 덱에 넣는다 (건너뛰기 가능). 후보는 **보유 64명 중** 성급으로 뽑는다.

| 성급 | 제안 확률 (성 1~5) | (성 6~12) | (성 13~19) |
| :---: | :---: | :---: | :---: |
| ★1~2 | 70% | 50% | 30% |
| ★3 | 20% | 30% | 30% |
| ★4 | 8% | 15% | 25% |
| ★5~6 | 2% | 5% | 15% |

* **같은 동료를 여러 장 넣는 것이 전략의 전부다.** 세바스찬을 4장 넣으면 덱 12장 중 1/3 → 열 하나 돌려 세바스찬 둘 이상 나올 확률이 눈에 보이게 오른다. LBaL 에서 "덱을 얇게 하는" 전략이 여기서는 "한 동료로 몰아 주는" 전략으로 바뀐다.
* **제명 토큰**: 보스를 죽이면 1개. 덱에서 카드 한 장을 영구 제거. (몰아주기의 반대 손잡이)
* 덱 상한 없음. 덱이 커질수록 한방은 어려워지고 1단 공격의 종류는 다양해진다 — 유저가 고르는 축이다.

## 3. 턴

```
[1] 하트 지불      열 하나 = betHeart[bet] × 1,  전부 = betHeart[bet] × 2
[2] 낙하           고른 열의 3장이 아래로 빠지고 덱에서 새 3장이 위에서 떨어진다
[3] 줄 판정        8줄을 보고 3·2·1 단계를 정한다 (한 카드는 최고 단계 하나)
[4] 동료 공격      turnList = [3단 줄들] → [2단 쌍들] → [돌린 열의 1단 카드들]
[5] 히어로 공격    무기 평타 1회 (장비는 그대로 히어로 것)
[6] 적 공격        살아 있는 적이 히어로를 때린다
[7] 소멸·보충      2·3단으로 터진 칸이 비고, 그 열의 위 카드가 내려오고 빈 자리에 새 카드가 떨어진다 (3매치 낙하)
[8] 처치 보상      적이 죽었으면 골드 + 동료 카드 3택1 → 다음 웨이브 적 등장
```

* **[7] 의 낙하는 공짜다**. 이것이 "액션 한 번에 패턴이 바뀌고, 랜덤 드랍이 다음 수를 바꾼다" 의 실체다. 터진 뒤 떨어진 카드가 우연히 새 쌍을 만들면 다음 턴의 선택이 바뀐다. 연쇄(터진 뒤 또 줄) 는 **두지 않는다** — 연쇄는 유저 선택 없이 터져 "내가 만든 한방" 감각을 깎는다.
* **홀드 없음, 스왑 없음.** 행동은 "어느 열을 돌릴까 + 베팅 얼마로" 둘뿐이다. 두 축만 있어야 바로 읽힌다.

### 3-1. 한방을 만드는 과정 (유저가 실제로 하는 것)

1. 베팅 ×1 로 싸게 돌리며 판을 깐다. 1단 공격으로 적을 조금씩 깎는다.
2. 어느 줄에 같은 동료 둘이 서면 **멈춘다**. 남은 한 칸이 속한 열을 보고, 덱에서 그 동료 확률(예 3/10)을 본다.
3. 덱이 약하면 몇 턴 더 돌리며 **3택1 로 그 동료를 덱에 더 넣는다**. 또는 제명으로 잡카드를 뺀다.
4. 확률이 마음에 들면 **베팅을 ×10·×30 으로 올리고 그 열 하나만 돌린다.** 맞으면 궁극기 × 30 — 적이 통째로 날아간다. 틀려도 그 열의 1단 공격은 ×30 으로 나간다 (헛방은 아니다).
5. 터지면 줄이 비고 새 카드가 떨어져 판이 바뀐다. 1 로 돌아간다.

→ 3매치와 같은 "본다 → 고른다 → 터진다 → 판이 바뀐다" 의 리듬이고, 베팅이 "지금이 그때다" 의 레버다.

## 4. 적과 난이도

* **적 체력이 난이도의 전부다.** 적 공격력·특수 패턴은 지금 값 그대로 두고 **체력 곡선만** 손본다.
* 성 하나 = 웨이브 10개. `wave_rule.tsv` 그대로: 5번째 소보스, 10번째 중보스, 100번째(=10성) 대보스.
* 체력 기준점 (첫 성): 튜토리얼 수치를 그대로 쓴다.

| 자리 | 체력 | 뜻 |
| :--- | :---: | :--- |
| 웨이브 1~4 잡몹 | 330 (`WAVE_HP_BASE`) | 베팅 ×1 로 1단 공격 열 대 안팎 |
| 5 소보스 | 330 × `WAVE_HP_SUBBOSS_MUL` | 2단 쌍 두세 번 또는 3단 한 방 |
| 10 중보스 | 330 × `WAVE_HP_MIDBOSS_MUL` | **3단 한 방 × 베팅 ×3 이상** 이어야 죽는다. 1단만으로는 하트가 먼저 바닥난다 |

* 성이 하나 넘어갈 때마다 체력 ×1.17 (`WAVE_HP_TIER_MUL`). 이미 있는 곡선이고, 보스 배수는 잡몹 기준이라 어느 성에서든 "한방이 몇 번 필요한가" 의 감각이 같다.
* **적은 매 턴 히어로를 때린다.** 히어로 체력 0 = 런 종료, 덱 소멸. 여기가 "미루면 죽는다" 의 압박이다. 보스는 평타의 2배.
* **클리어 = 10번째 보스 처치.** 그 성의 보상(골드·장비 드랍)을 받고 다음 성으로. 19성 전부 넘기면 무한 모드 (체력 ×1.17 계속).

## 5. 하트와 베팅 (경제)

| 재화 | 쓰임 |
| :--- | :--- |
| 하트 | **턴마다 낸다** (지금 그대로). 열 하나 = `betHeart[bet]`, 전부 = ×2. 하트가 바닥나면 돌릴 수 없고, 적은 계속 때린다 → 사실상 두 번째 패배 조건 |
| 베팅 | 하트 ×배수 = 피해 ×배수. 한방의 레버. 런 중 언제든 바꾼다 |
| 골드 | 적 드랍. 런 중 **리롤(3택1 다시 뽑기)** 과 **제명 토큰 추가 구매**. 런 밖 장비 강화 |
| 장비 | 히어로 것. 런 밖에서 키운 영구 스탯. 런 안에서는 바뀌지 않는다 (v1 의 임시 장비 안은 **버림** — 레버가 셋이면 안 읽힌다) |

하트를 스핀마다 내는 지금 구조를 **유지**한다 (v1 과 반대). 이유: "싸게 깔다가 비싸게 터뜨린다" 의 긴장이 하트 지불에서 나온다. 스핀이 공짜면 베팅을 올릴 이유만 남고 "지금 돌릴까 말까" 가 사라진다.

## 6. 동료 64명의 자리

성급·역할군·스킬 번호는 건드리지 않는다. 역할군은 **3단 스킬이 무엇이냐** 로 이미 갈려 있다:

| 3단 종류 | 인원 | 줄이 되면 |
| :--- | :---: | :--- |
| HEROSKILL | 29 | 현재 히어로의 궁극기(로빈 소울크래시 / 다이애나 / 맥스)가 나간다. **한방 그 자체** |
| SUMMON · CREWSUMMON · SUMMONHERO | 35 | 소환수가 나와 **다음 3턴** 동안 매 턴 때린다. 지속형 한방 |
| CREWBULLET (3단도 탄) | 7 | 탄 ×N. 순수 피해형 |

역할군 추가 규칙은 하나만 둔다 (와일드):
* **지휘형 17명은 와일드다.** 줄 안에서 어떤 동료로도 센다. 단 와일드 3장만으로는 줄이 안 된다 (와일드 2 + 진짜 1 까지). 슬롯의 와일드 심볼이라 설명 없이 읽힌다.

인접 효과·성장·소비는 **없다**. 줄과 와일드, 둘뿐.

## 7. 바로 읽히는지 자가 점검

| 3매치의 요소 | v2 의 대응 |
| :--- | :--- |
| 같은 색 3개 = 터짐 | 같은 동료 3장 한 줄 = 궁극기 |
| 내가 스왑한다 | 내가 열 하나를 돌린다 |
| 터지면 위에서 떨어진다 | 터진 칸은 위 카드가 내려오고 새 카드가 떨어진다 |
| 떨어진 것이 다음 수를 바꾼다 | 안 터진 카드는 남고, 떨어진 카드가 새 쌍을 만든다 |
| 가운데가 비싸다 | (1,1) 은 4줄에 걸친다 |
| 큰 한방을 노린다 | 쌍을 세워 두고 베팅을 올려 마지막 열을 돌린다 |
| 턴/시간 제한 | 적이 매 턴 히어로를 때린다, 하트가 준다 |
| 스테이지 목표 | 적 체력 0 (보스면 성 클리어) |

## 8. 확률 감각 (설계 검증용)

덱 D 장, 그 동료 k 장. 열 하나를 돌려 3칸 중 **특정 칸** 에 그 동료가 올 확률 = k/D.

| 덱 구성 | 마지막 한 칸 맞힐 확률 | 뜻 |
| :--- | :---: | :--- |

# v3 안 — 2048 합성 × 3릴 룰렛 × 턴 적립 (2026-11-08, 사용자 제안)

> v2 의 "줄 맞추기" 를 버리고, **블록을 합쳐 키우고 쌓아 두었다가 한 번에 쏟아붓는** 구조로 바꾼다.
> v2 에서 살리는 것: 동료 1·2·3단 스킬, 적 체력 = 난이도, 턴제. (베팅 레버는 2026-11-09 에 삭제 — §17)

## 1. 한눈에

```
  룰렛 남은 횟수 7/10        적 체력 ████████░░  방어 12
 ┌───┬───┬───┬───┬───┐
 │세바│   │로키 로키│   │      ← Lv2 (1×2)
 ├───┼───┼───┴───┼───┤
 │   │엘사 엘사│    │   │
 ├───┤엘사 엘사├───┼───┤      ← Lv3 (2×2) = 궁극기 한 방
 │꼬마│       │세바│   │
 ├───┼───┬───┼───┼───┤
 │   │   │   │   │   │
 └───┴───┴───┴───┴───┘
   [더 돌리기 ♥1]  트레이: [세바][로키][꼬마]        [지금 공격 ♥1]
```

* **판**: 6×6 = 36칸. 적 하나와 싸우는 동안 블록을 쌓는 캔버스. (5×5 는 10회분 30칸이 물리적으로 안 들어가 8턴쯤에 강제 공격이 걸린다. 아래 §1-1.)
* **룰렛**: 3릴. 돌리면 동료 블록 3개가 트레이로 나온다. 적 하나당 **10회**.
* **합성**: 같은 동료 · 같은 레벨 둘을 합치면 한 단계 위. **커진다**: Lv1 1×1 → Lv2 1×2 → Lv3 2×2.
* **공격**: 언제든 누른다. 판 위 블록이 전부 날아가 적을 때리고 판이 빈다. 매 턴 눌러도 되고 10턴 모아 한 번에 눌러도 된다.
* **적은 내가 공격했을 때만 때린다.** 공격 한 번 = 턴 교환 한 번. 모으는 동안은 맞지 않는다 (§5).

### 1-1. 판 크기 산정

합쳐도 칸이 줄지 않으므로 판이 들고 있어야 하는 칸 수 = 룰렛 횟수 × 3 이다.

| 판 | 칸 | 10회분 30칸 | 뜻 |
| :---: | :---: | :---: | :--- |
| 5×5 | 25 | 안 들어감 | 8턴쯤 자리가 막혀 강제 공격. "10턴 모아 한방" 이 성립하지 않는다 |
| **6×6** | **36** | 여유 6칸 | 10턴을 다 모을 수 있되, 2×2 네 개를 흩뿌리면 막힌다. 정리할 이유가 남는다 |
| 7×7 | 49 | 여유 19칸 | 정리가 필요 없어진다. 칸 압박이 사라진다 |

화면: 설계 해상도 640 폭에서 6칸이면 칸당 약 90px (좌우 여백 뺀 뒤), 2×2 블록 180px 로 손가락 조작에 충분하다. 7칸부터는 75px 아래로 떨어져 1×1 블록 집기가 불편해진다.

## 2. 블록과 레벨 (RH 데이터 그대로)

| 레벨 | 크기 | 쏘는 것 | 피해 |
| :---: | :---: | :--- | :--- |
| Lv1 | 1×1 | `SKILL1` 일반탄 | 100% |
| Lv2 | 1×2 | `SKILL2` 일반탄 | 300% |
| Lv3 | 2×2 | `SKILL3` 히어로 궁극기 / 소환 | 궁극기 값 |
| Lv4 `[v3.1]` | 2×4 | **각성** — `SKILL3` ×3, 전체 컷인 | 궁극기 ×3 |

* **합쳐도 칸이 줄지 않는다** (1+1=2, 2+2=4). 합성의 이득은 칸이 아니라 **칸당 화력**이다 (100 → 150 → 궁극기/4칸). 그래서 36칸이 곧 "쌓을 수 있는 한계" 다. 룰렛 10회 × 3개 = 30칸은 들어가되 여유가 6칸뿐이라 2×2 를 아무렇게나 두면 막힌다. **턴이 한도를 정하고, 칸은 정리를 요구한다.**
* `[v3.1]` Lv4 를 연다. 계열이 셋이라 계열당 10장이 들어오고, 3단에서 멈추면 합성이 작업이 된다(§15-2). Lv4 는 새 데이터가 아니라 3단 ×3 이다.
* **릴 매치는 그대로 산다**: 3릴에 같은 동료가 둘이면 **Lv2 블록으로 나온다**, 셋이면 **Lv3 으로 나온다**. 지금의 `GetSameRouletteCnt()` 가 하던 일이다. 룰렛이 단순 뽑기가 아니라 "운 좋으면 합성을 건너뛴다" 가 된다.

## 3. 합성·배치 규칙 (읽히게 하려고 줄인 것)

* **합성에 인접은 필요 없다.** 블록 A 를 집어 같은 동료·같은 레벨인 B 에 놓으면 B 자리에서 커진다. 커진 크기가 B 자리에 안 들어가면 합칠 수 없다 (빨간 표시). 인접을 요구하면 2048 식 "밀어서 맞추기" 가 되어 크기가 다른 블록과 뒤엉킨다.
* **옮기기는 공짜·무제한.** 턴을 쓰는 것은 룰렛뿐이다. 정리는 퍼즐이지 자원이 아니다.
* 트레이의 블록은 **판에 놓아야 다음 룰렛을 돌릴 수 있다.** 놓을 자리가 없으면 공격해서 비우는 수밖에 없다 — 이것이 "강제 공격" 이고 턴 종료와 같은 역할이다.
* 룰렛 10회를 다 쓰면 공격만 남는다. 공격 뒤 적이 살아 있으면 **룰렛 10회가 다시 찬다** (라운드 2). 즉 10회는 "한 번의 적립 한도" 지 패배 조건이 아니다. 패배 조건은 히어로 체력뿐.

## 4. 공격과 하트 `[2026-11-09 베팅 삭제]`

* **룰렛 1회 = 하트 1.** 싸다.
* **공격 = 하트 1.** 베팅·피해 배수는 없다. 한방의 크기는 오직 판 위에 무엇을 얼마나 합쳐 쌓았느냐다. 매 턴 공격하면 공격 하트가 매 턴 나가고(10턴에 20), 모아 쏘면 한 번(11)이다 — 두 플레이가 하트 경제에서 갈린다.
* (삭제 전 안) 공격 시 베팅 ×1~×100 으로 하트와 피해를 같이 곱하는 레버가 있었다. "산 한방" 이 되고 레버가 하나 더 생겨 읽기를 흐리므로 뺐다. 과금은 하트 소비량 자체로 간다(§12).
* 발사 순서 = `turnList`: Lv3 → Lv2 → Lv1, 같은 레벨 안에서는 판의 왼쪽 위부터. 히어로가 마지막에 평타.
* **적 방어력 (`PS_DEFENSE`, 타격당 차감)** 이 두 플레이를 가른다. 방어 낮은 잡몹은 Lv1 을 매 턴 쏟아도 죽는다. 방어 높은 보스는 Lv1 이 다 깎여 **Lv3 궁극기 아니면 안 박힌다**. 난이도의 주축은 체력, 보조 축이 방어. 둘 다 이미 있는 스탯이다.

## 5. 턴 흐름 — 공격했을 때만 턴을 주고받는다 (2026-11-08 변경)

```
적 등장 (판 비움, 룰렛 10회)
  ┌─ 적립 ──────────────────────────────────────────┐
  │ [룰렛]  하트 1. 3릴 → 트레이 3개 (릴 매치면 Lv2/3)    │   ← 적은 가만히 있다
  │ [배치·합성]  자유. 트레이를 다 놓아야 다음 룰렛         │
  └─────────────────────────────────────────────────┘
  [공격]  누르면 (룰렛 0회면 강제) ──▶ 내 턴: 하트 1 내고 판 전부 발사, 판 비움
                                  ──▶ 적 턴: 적이 히어로를 한 번 때린다
                                  ──▶ 룰렛 10회 재충전, 적립으로
적 사망 → 골드·드랍 → 다음 웨이브.  히어로 체력 0 → 종료
```

* **적은 내가 공격했을 때만 때린다.** 룰렛을 돌리고 정리하는 동안은 가만히 있다. 공격 한 번 = 턴 한 번의 교환.
* 그러면 "모으는 동안 맞는다" 는 압박이 없어진다. 대신 압박은 **둘**에서 온다:
  * **하트**: 룰렛 1회 하트 1 은 언제 쏘든 같이 나가지만, **공격 하트 1 은 공격 횟수만큼** 나간다. 열 번 나눠 쏘면 열 번이다.
  * **히어로 체력**: 적 턴은 공격 횟수만큼 온다. 교환을 줄일수록 체력이 남고, 그 체력이 성 끝까지 간다.
* 그래서 두 플레이는 이렇게 갈린다. **지금 판으로 죽일 수 있으면 바로 쏜다** (하트·체력 절약, 넘치는 피해는 버려진다). **못 죽이면 모은다.** 화면에 **예상 피해 vs 적 체력** 을 항상 띄워 그 판단을 한눈에 하게 한다.
* 넘치는 피해는 다음 적에게 넘어가지 않는다. 잡몹에 10턴을 모아 쏘는 것은 하트 낭비다 — 이것이 "매 턴 공격" 이 살아 있는 이유다.
* 룰렛 10회를 다 쓰면 공격만 남는다. 공격 뒤 적이 살아 있으면 교환이 끝난 뒤 10회가 다시 찬다.

## 6. 난이도 = 적 체력

* 체력 곡선은 지금 것(`WAVE_HP_BASE 330`, 계단 ×1.17, 보스 배수) 그대로.
* 기준 한 줄: **첫 성 중보스는 "Lv3 두 개 + Lv2 셋 정도를 10턴에 쌓고 ×3 으로 쏘면 죽는다."** 이 문장이 `WAVE_HP_MIDBOSS_MUL` 과 보스 방어력을 정한다.
* 편성 6명이 릴의 심볼 6종이다. 6종이라 같은 동료가 자주 겹쳐 합성이 막히지 않는다. (LBaL 식 덱 성장은 v3 에서는 **보류** — 종류가 늘면 합성이 안 되고 읽기가 흐려진다. 넣더라도 "편성 7번째 칸을 런 중에 산다" 정도.)

6. 세이브: 런 상태 `{lineage[3], 판, 트레이, 잔여 룰렛, 목숨}`. 구조체 끝에 붙인다. `server/schema.sql` 동일.
7. 튜토리얼 4컷: 시작 슬롯 → 돌린다 → 합친다 → 쌓아서 쏜다. `DEMO_TUTORIAL_ROULETTE*` 대사 교체.
8. ACTIONRPG 는 건드리지 않는다. `option.gameMode == TURNRPG` 분기 안에서만 산다.

## 9. 가정

1. `[v3.1]` 판 6×6, 룰렛 10회, 계열 3, 레벨 4(크기 1·2·4·8). 판 크기는 "룰렛 전 횟수 × 3 + 6칸 여유" 로 묶어서 같이 움직인다.
2. 합성에 인접 불필요, 옮기기 무제한.
3. 룰렛 1회 하트 1, 공격 1회 하트 1. 베팅 없음 (2026-11-09 삭제).
4. 적은 내가 공격했을 때만 한 번 때린다 (턴 교환). 룰렛·정리 중에는 때리지 않는다. 압박은 공격 하트와 목숨, 그리고 넘치는 피해가 버려지는 것에서 온다.
5. `[v3.1]` 심볼은 시작 슬롯이 정한 계열 3(릴 1 선택 + 릴 2·3 무작위, 동료·장비 섞임). LBaL 덱 성장은 보류.
6. 공격 버튼은 "지금 공격 ♥1" 하나, 룰렛 버튼은 "더 돌리기 ♥1". 매 턴의 결정은 이 둘뿐이다.

## 10. 판에 올라가는 것의 종류 (2026-11-08 결정)

### 10-1. 판에는 계열 블록만 올린다 `[v3.1 수정]`

* **판 위의 블록은 시작 슬롯이 정한 계열 3 뿐이다.** 동료든 장비든 뽑힌 것만 올라온다. 뽑히지 않은 장비는 판 밖 3칸의 영구 스탯으로만 산다(§10-3).
* (v3 원문) 판 위의 블록은 동료 한 종류뿐이다 — 이 결정은 "종류를 섞으면 합성이 깎인다" 때문이었고, v3.1 은 종류를 셋으로 못 박아 그 문제를 없앴다.
* 이유: 합성의 식별 단위는 "같은 얼굴" 이어야 한다. 투구·장갑 아이콘은 레벨 색을 입히면 서로 구분이 안 되고, 얼굴은 색이 바뀌어도 알아본다. 그리고 동료 64명·3단 스킬·릴 매치는 RH 가 이미 들고 있다.
* 운빨존많겜이 하는 것과 같다. 판에는 유닛만, 유닛은 등급마다 **고정된 소수**(등급당 5종), 등급은 색으로.

### 10-2. 룰렛 족보 — 심볼 5종, 손 3가지 `[v3.1 에서 심볼 3·레벨 4 로 바뀜, §15]`

룰렛이 낼 수 있는 것의 가짓수가 게임의 폭이다. 너무 많으면 같은 것이 안 모여 합성이 안 되고, 너무 적으면 매 판이 같다.

**심볼 수 N 과 30장(룰렛 10회 × 3)의 관계**

| N | 종류당 장수 | 종류당 합성 결과 | 남는 조각 | 한 스핀에 짝(2) | 한 스핀에 셋(3) | 느낌 |
| :---: | :---: | :--- | :---: | :---: | :---: | :--- |
| 3 | 10 | Lv3 2 + Lv2 1 | 0 | 78% | 11% | 매 스핀 짝이 뜬다. 합성이 선택이 아니라 작업 |
| 4 | 7.5 | Lv3 1 + Lv2 1 + Lv1 1.5 | 1~2 | 63% | 6% | 좋다. 다만 2048 처럼 한 가지 색이 판을 덮는다 |
| **5** | **6** | **Lv3 1 + Lv2 1** | **0** | **52%** | **4%** | **30장이 딱 떨어진다.** 두 스핀에 한 번 짝. 3매치의 5색과 같은 폭 |
| 6 | 5 | Lv3 1 + Lv1 1 | 1 | 44% | 3% | Lv2 가 안 남는다. 종류당 한 번의 Lv3 를 만들고 끝 |
| 8 | 3.75 | Lv2 1 + Lv1 1.75 | 2 | 33% | 1.6% | Lv3 가 안 나온다. 모아도 한방이 없다 |

* **N = 5.** 종류당 6장은 Lv3 하나(4장) + Lv2 하나(2장)로 남김 없이 떨어진다. 5종 × (Lv3 + Lv2) = 20 + 10 = 30칸, 36칸 판에 여유 6 — §1-1 과 맞물린다. 짝이 두 스핀에 한 번이면 "뭔가 됐다" 가 지루하지 않을 만큼 온다.
* (v3) 그래서 **런에 데려가는 동료는 5명** (편성 `MAXCREW 6` 중 5 선택). `[v3.1: 릴 1 선택 1 + 무작위 2]` 64명은 "누구 5명이냐" 의 폭이지 한 판의 폭이 아니다. 성급·3단 종류(궁극기/소환/탄)가 다른 5명을 고르는 것이 런 밖 전략이다.
* **손(족보)은 셋뿐이다.** 3릴을 보고 바로 읽혀야 한다.

| 손 | 3릴 | 트레이로 오는 것 | 확률 (N=5) |
| :--- | :--- | :--- | :---: |
| 꽝 | 셋 다 다름 | Lv1 ×3 | 48% |
| 짝 | 둘 같음 | **Lv2 ×1** + Lv1 ×1 | 48% |
| 셋 | 셋 같음 | **Lv3 ×1** | 4% |

  스트레이트·역할군 조합 같은 넷째 손은 두지 않는다. 손이 넷이면 "이게 뭐였지" 가 생긴다.
* 특수 심볼(와일드·폭탄)은 v3 에 없다. 넣는다면 **6번째 심볼 하나**를 와일드(아무 동료와 합성됨)로 — 그때도 N 은 6 을 넘기지 않는다.
* 레벨 색은 **동료와 무관하게 고정**: Lv1 구리, Lv2 은, Lv3 금. 시안에서 Lv2 가 초록·파랑으로 갈린 것은 안 된다 — 색이 레벨을 말해야 한다.

### 10-3. 장비는 3칸, 역할 하나씩

RH 의 8부위(무기·투구·갑옷·바지·장갑·신발·목걸이·반지)를 다 쓰지 않는다. 판 밖 레버는 셋이면 충분하고, 셋이 넘으면 "뭘 올려야 세지는가" 가 안 읽힌다.

| 칸 | RH 부위 | 역할 | 수치가 닿는 곳 |
| :--- | :--- | :--- | :--- |
| **무기** | `EQUIP_WEAPON` | 공격 | 모든 블록 피해의 기준값 (지금도 첫 검 10 → 실제 한 대 33). 궁극기도 이 값에 비례 |
| **갑옷** | `EQUIP_ARMOR` | 버팀 | 성 하나당 **목숨 수** (§5 의 교환 횟수). 기본 3, 갑옷으로 +1·+2 |
| **목걸이** | `EQUIP_NECK` | 경제 | 룰렛 횟수 +1, 공격 하트 환급, 릴 매치 확률 보정 중 하나 |

* 나머지 5부위는 **쓰지 않는다**. 열거는 남겨 두고(세이브 계약) UI 와 드랍에서 뺀다.
* 장비는 런 중에 바뀌지 않는다 (v3 §4·§9 그대로). 런 밖에서 키운다.

### 10-4. 시안에서 빠질 것

* 적 머리 위 "방어 12" — 방어력은 없다 (§4 결정 전제). 적은 체력 바 하나.
* 상단 HP 바 — 히어로 체력 스탯 대신 **목숨 아이콘 N개**. 적 턴마다 하나 꺼진다.

### 10-5. 공격만 있다, 방어는 없다

* 룰렛은 **공격 블록만** 낸다. 방패·회복 블록을 내지 않는다.
* 이유 둘. (1) 심볼이 하나 늘 때마다 종류당 장수가 30/N 으로 준다 — 방어 심볼 하나가 모든 동료의 합성을 깎는다. (2) 판 위의 결정은 "지금 쏘나, 더 모으나" 하나여야 한다. "방패를 남겨 둘까" 가 끼면 결정이 둘이 된다.
* 방어는 **판 밖에 수동으로** 둔다: 목숨 N개(갑옷), 적 턴마다 하나. 유저가 방어를 "하는" 일은 없고, 교환을 줄이는 것이 곧 방어다. 운빨존많겜도 같다 — 유닛은 때리기만 하고, 버티는 것은 목숨 수다.
* 공방이 필요해지는 때는 **PVP** 뿐이다. 그때도 상대 판을 때리는 것이지 방패 블록이 생기는 것이 아니다 (v4 과제).

### 10-6. 몬스터는 블록이 아니라 결과다

* 몬스터는 판에 올리지 않는다. 판에 올리는 순간 "동료 아니면 몬스터" 두 종류가 되어 10-1 이 무너진다.
* 몬스터는 이미 **Lv3 의 결과물**이다. 동료 64명 중 35명의 3단이 SUMMON 계열이고(`skill.tsv` `summon_enemy`: 검은 유령선, 파란 슬라임, 초록 골렘 …), 이 소환수가 필드에 나와 **다음 3교환 동안** 매 교환마다 때린다. "몬스터를 데려다 쓴다" 는 재미는 여기서 난다.
* 나중에 넣을 수 있는 것: 보스를 쓰러뜨리면 그 보스를 동료로 포획(428 몬스터가 수집 대상이 됨). v3 에서는 보류. 64명을 다 보여 주기 전에는 풀을 넓히지 않는다.

## 11. 연출 — 쾌감이 나는 자리 다섯

쾌감은 "기대를 쌓았다가 한꺼번에 푼다" 에서 난다. 쌓는 자리 셋, 푸는 자리 둘.

| 자리 | 무엇이 보이나 | 어떻게 |
| :--- | :--- | :--- |
| **① 릴 매치** | 3릴에 같은 얼굴이 둘·셋 서는 순간 | 지금 `RouletteDraw()` 연출 그대로. 둘이면 트레이에 **Lv2 가 이미 커진 채로** 떨어지고, 셋이면 Lv3 가 2×2 로 쿵 하고 떨어진다. 슬롯의 "777" 과 같은 자리라 소리·플래시를 가장 세게 |
| **② 합성** | 블록을 같은 블록 위에 놓는 순간 | 두 블록이 빨려 들어가 **커지면서** 스쿼시, 판이 한 번 흔들림. 레벨 색이 구리→은→금으로 바뀐다 |
| **③ 예상 피해 카운터** | 공격 버튼 위의 숫자 | 블록을 놓고 합칠 때마다 숫자가 **또르륵 올라간다**. 적 체력을 넘는 순간 버튼이 금색으로 바뀐다 ("지금 쏘면 죽는다"). 합성 한 번에 숫자가 크게 튄다. 한방을 "쏘기 전에" 느끼게 하는 자리 |
| **④ 발사** | 공격 버튼 | 블록이 판에서 **레벨 순으로 떠올라** 날아간다. Lv1 은 열 개씩 묶어 탄막처럼 빠르게(0.1초 간격), Lv2 는 하나씩 묵직하게, **Lv3 는 화면이 멈추고 히어로 컷인 → 궁극기**(지금 HEROSKILL 연출). 피해 숫자는 각자 뜨지 않고 **적 머리 위 한 숫자에 누적**되고 HIT 카운트가 돈다(`hitCount` 그대로). 마지막에 **"×10" 도장**이 찍히며 누적 숫자가 한 번 더 뛴다 |
| **⑤ 처치·오버킬** | 적 체력 0 | 넘친 피해만큼 "OVERKILL +2,340" 배너. 보스면 성이 흔들리고 금화가 쏟아진다. 10턴을 모았다가 한 번에 쏜 판일수록 여기가 길어야 한다 |

* 판이 비는 것 자체가 보상이다. 30개 블록이 전부 날아가 빈 판이 되는 1~2초가 "다 쏟아부었다" 의 감각.
* 매 턴 쏘는 플레이는 ④ 가 짧고(블록 셋), 모아 쏘는 플레이는 ④ 가 길다. 연출 길이가 곧 선택의 보상이라 **빠른 모드에서도 Lv3 컷인은 자르지 않는다**.

## 12. 성장과 과금

### 12-1. 성장 축은 셋

| 축 | 무엇이 자라나 | 지금 RH 에 있는 것 | 판에서 보이는 자리 |
| :--- | :--- | :--- | :--- |
| **동료** | 64명 수집 + 성급(★1~6)별 스킬 값 | `crew.tsv`, 가챠(`Func_Gacha.cpp`), `reward_crew` | 누구 5명을 데려가나. ★ 높은 동료의 Lv3 가 더 세다 |
| **장비 3칸** | 무기(피해 기준값) · 갑옷(목숨) · 목걸이(룰렛/하트) | 무기 35자루 등비 ×1.145, 상자 드랍(`MakeBoxEquipType`), 강화 | 무기가 적 체력 곡선(×1.17/성)과 맞물린다. 벽은 늘 무기다 |
| **성** | 19성 × 웨이브 10. 체력 ×1.17 | `castle.tsv`, `WAVE_HP_*` | 어디까지 갔나 |

* **동료 레벨은 두지 않는다.** 성급이 곧 세기이고, 같은 동료를 더 뽑으면 성급이 오르는 식(운빨존많겜의 "같은 유닛 N개 → 승급")으로 중복 뽑기를 소화한다.
* 성장의 벽은 하나여야 한다: **무기**. 동료·목걸이는 벽이 아니라 "더 빨리·더 싸게" 다. 벽이 둘이면 뭘 사야 할지 모른다.

### 12-2. 과금은 하트가 중심, 나머지는 셋

| 상품 | 무엇을 사나 | 있는 것 | 왜 산다 |
| :--- | :--- | :--- | :--- |
| **하트** | 룰렛 1회 = 하트 1, 공격 1회 = 하트 1 | `Func_Iap.cpp`, 하트 패스(`HEARTPASS_REGENMUL 2`, 보너스 상한 50) | 성 하나(적 10) 를 도는 데 적당 11~20. **행동 횟수가 곧 과금 레버**다. 하트가 없으면 돌리지 못하고, 있는 판으로 쏘고, 목숨을 쓴다 |
| **동료 뽑기** | 64명 가챠 | `Func_Gacha.cpp` | ★5·6 의 Lv3 가 세다. 중복은 승급 |
| **성장 패스** | 골드 +20% (`GROWTHPASS_GOLDPER`) + 룰렛 횟수 +1 + 리롤 1회/적 | 패스 틀 있음 | 매 판 조금 유리. 운빨존많겜의 패스와 같은 자리 |
| **광고** | 목숨 +1 / 룰렛 +3 / 트레이 리롤 | `AdmobLib` | 무과금의 숨구멍. 보스 직전 "한 번만 더" |

* **팔지 않는 것**: 피해 배수, 판 크기, 레벨 4. 판 위의 규칙을 팔면 "내가 만든 한방" 이 "산 한방" 이 된다. (베팅을 뺀 이유도 이것이다)
* **광고로 주지 않는 것**: 하트 직접 지급. 하트가 광고로 풀리면 행동 횟수가 공짜가 된다. 광고는 횟수·목숨 같은 **그 판 안의 것**만.

### 12-3. 한 판의 과금 순간

```
보스 앞. 7턴 모았고 예상 피해 = 체력의 70%. 룰렛 3회가 남았다.
  → 세 번 더 돌려 합치면 넘는다. 하트 3 + 공격 1.   (하트 잔량이 여기서 보인다)
  → 하트가 2 뿐이다.
  → [광고] 목숨 +1 로 지금 쏘고 한 번 더 모으기  /  [하트 구매] 세 번 더 돌려 한 방
```
이 갈림길이 과금의 전부다. 다른 곳에서 돈을 받지 않는다.

### 10-7. 장비 3칸을 전투 화면의 코스튬으로

RH 히어로 스프라이트는 **6겹**이다: 무기·투구·갑옷·바지·장갑·신발(`COSTUME_*_ROBIN/DIANA/MAXX_IMG`, 히어로마다 따로). 목걸이·반지는 겹이 없다. 장비를 3칸으로 줄여도 6겹은 다 쓴다.

| 칸 | 코스튬에 닿는 겹 | 규칙 |
| :--- | :--- | :--- |
| **무기** | 무기 겹 1개 | 지금 그대로. 자루마다 그림이 다르고, 블록이 날아갈 때 히어로가 그 무기를 휘두른다 |
| **갑옷** | 투구·갑옷·바지·장갑·신발 **5겹을 한 세트로** | 갑옷 `detail N` 을 끼면 같은 N 번 투구·바지·장갑·신발이 **따라 입혀진다**. 세트 다섯 부위를 따로 팔지 않으니 "갑옷 하나 = 외형 한 벌" 이 된다. 5겹 그림은 이미 있으므로 새로 그릴 것이 없다 |
| **목걸이** | 겹 없음 → **히어로 발밑 오라 색** | 목걸이 등급에 따라 발밑 원광(기존 `effect` 계열)의 색. 작게 보이되 "뭔가 끼고 있다" 는 알린다. 보스 앞 광고 버튼 옆에 표시되는 것도 이 색 |

* 결과: 히어로 외형을 정하는 축은 **무기 + 갑옷 둘**이고, 둘 다 "세진 만큼 달라 보인다". 운빨존많겜의 유닛 스킨과 달리 외형이 곧 스탯이라, 외형만 파는 상품(스킨)은 두지 않는다 — 외형이 거짓말을 하면 안 된다.
* **동료는 판 위 블록과 전투 화면 둘 다에 선다.** 런에 데려간 5명이 히어로 뒤에 서 있고(지금 `ao[CREW+k]` 그대로), 블록이 날아갈 때 **그 동료가 앞으로 나와 쏜다**. Lv3 면 히어로 컷인 뒤 그 동료의 3단 모션(`enemyAttackPattern` 단계별 블록). 판의 블록과 필드의 사람이 같은 얼굴이라 "누가 쐈는지" 를 두 번 설명할 필요가 없다.
* 합성 레벨은 코스튬이 아니라 **블록 테두리 색**(구리·은·금)에만 있다. 동료 외형을 레벨마다 바꾸면 64 × 3 장을 그려야 하고, 얼굴이 바뀌면 합성 식별이 깨진다.

### 13-2. 이 게임이 "족보 수" 를 푼 방법

* **한 등급 안의 종류는 4~6.** 그래서 같은 것 3개가 모인다. 전체 유닛은 수십 종이지만 **한 번에 보는 폭은 등급 하나의 5종** 이다. → 우리 §10-2 의 N=5 와 같은 답.
* **합성 결과를 무작위로** 두어 종류가 적은데도 빤하지 않다. "3개 모으면 뭐가 나올까" 가 매 합성의 작은 뽑기다. → 우리는 결과가 정해져 있다(같은 동료 Lv↑). **대신 릴 매치가 그 뽑기 역할**을 한다. 둘 다 "운이 두 번" 이다: 그쪽은 뽑기+합성, 우리는 시작 슬롯+릴.
* **등급이 5단**이라 한 판이 길다(40~80라운드). 우리는 3단에 10턴이라 **한 적을 상대하는 한 판이 짧다**. 그쪽의 "신화 레시피" 같은 장기 목표는 우리에게 없다 — 필요하면 "특정 동료 셋의 Lv3 를 한 판에 다 쏘면 보너스" 같은 자리가 그 대응이다. v3 에는 넣지 않는다.
* **빤함 방지 장치는 유닛 종류가 아니라 "뽑기 비용 상승 + 유닛 상한 25 + 몬스터 100"** 세 압박이다. 종류를 늘리지 않고 압박을 늘려 빤함을 막았다. → 우리는 "룰렛 10회 + 36칸 + 목숨" 이 같은 자리다.

### 13-3. 공방을 어떻게 풀었나

* **공격 유닛뿐이다.** 방패·회복 유닛은 없다. 지원형이 있지만 "마나 회복·둔화·기절" 로, 전부 **더 잘 때리기 위한** 것이다.
* **방어는 숫자 하나**: 필드의 몬스터 수 100. 못 죽이면 쌓이고, 쌓이면 진다. 체력 바도 방어력도 없다.
* 보스는 **제한 시간** 으로 "순간 화력" 을 묻는다. 평소에는 "지속 화력" 을 묻는다(쌓이지 않게). 두 질문이 유닛 선택을 가른다.
* → 우리 §10-5 와 같다. 공격만, 방어는 목숨 수. 보스의 "제한 시간" 은 우리의 "룰렛 10회 안에" 다.

## 14. 턴제에서 특성은 "위치" 가 아니라 "순서와 상태" 에 건다

> 운빨존많겜의 특성(근/원·공속·쿨타임)은 전부 **실시간 + 위치** 위에 서 있다. 우리는 턴제에 위치가 없으니 그 축은 못 쓴다.
> 턴제가 대신 가진 것은 **순서가 눈에 보이고, 상태가 교환을 넘어 남는다** 는 것이다. 특성은 여기에 건다.

### 14-1. 발사 순서 = 판의 위치

* 공격을 누르면 블록은 **판의 왼쪽 위부터 읽는 순서**(행 우선)로 날아간다. Lv 순이 아니다.
* 그래서 **판의 자리가 곧 순서**다. 어디에 합성하고 어디에 두느냐가 "누가 먼저 때리느냐" 를 정한다. 이것이 턴제판 "위치 개념" 이다 — 사거리 대신 **타순**.
* 정리 단계에서 하는 일이 둘이 된다: 칸을 맞추는 것(테트리스) + 타순을 짜는 것(카드 순서). 둘 다 공격 버튼을 누르기 전에 머릿속에서 끝나므로 "고민해서 한 번에 정리하는" 쾌감이 그대로다.

### 14-2. 특성 6종 — 준비 2, 타격 2, 교환 2

동료 하나에 특성 하나. 레벨이 오르면 크기만 커진다(종류는 그대로). 런의 5명은 이 6종 중에서 고르게 된다.

| 자리 | 특성 | 하는 일 | 왜 턴제에서 사는가 |
| :--- | :--- | :--- | :--- |
| **준비** | **표식** (Expose) | 적에게 표식. 이후 이 판의 모든 타격 +30% (Lv2 +60%, Lv3 +100%) | 먼저 쏴야 한다. 타순의 앞에 둘 이유 |
| | **고무** (Inspire) | **바로 다음 블록** 의 피해 ×2 (Lv2 ×3, Lv3 ×4) | 다음에 누가 오느냐가 전부. Lv3 궁극기 앞에 붙이면 한방이 두 배 |
| **타격** | **강타** (Strike) | 피해 그 자체가 크다. 특성이 없다는 뜻이 아니라 "순수 화력" | 표식·고무가 올려 줄 대상. 타순의 뒤 |
| | **연타** (Volley) | 탄이 여럿. 적이 여럿일 때(multi2·3 웨이브) 전부 맞는다 | 단일 보스에는 약하고 잡몹 떼에는 세다. 웨이브에 따라 데려가는 5명이 바뀌는 이유 |
| **교환** | **빙결** (Chill) | 적의 **다음 턴을 지운다** (Lv3 만). Lv1·2 는 적 공격력 절반 | 목숨을 안 잃고 교환을 넘긴다. 방어 블록 없이 방어를 만드는 유일한 길. 운빨존많겜의 기절이 이 자리 |
| | **지속** (Burn·Poison) | 교환이 끝나도 남아 **다음 교환 시작에** 또 피해 (Lv 당 1교환씩 더) | 매 턴 쏘는 플레이와 모아 쏘는 플레이를 잇는다. 지속을 걸어 두고 모은다 |

* 특성은 전부 때리는 것을 돕거나(표식·고무·강타·연타), 교환을 넘기는 것(빙결·지속)이다. 방어는 여전히 없다.
* **"쿨타임"** 의 자리는 **Lv** 다. 운빨존많겜이 쿨타임으로 궁극기 빈도를 조절했다면 우리는 "Lv3 를 만들었느냐" 로 조절한다.
* **"근/원"** 의 자리는 **연타/강타** 다. 적이 하나냐 여럿이냐가 사거리 대신 갈라 준다.
* 64명 → 6특성 배정은 cs 쪽 64명 표의 Action 종류(Expose·Inspire·Strike·Volley·Chill·Burn·Poison …)를 그대로 쓴다. 거기 없는 종류(Heal·Repair·Shield·Supply·Cleanse·Leech …)는 가장 가까운 여섯 중 하나로 접는다. **RH 코드에는 이 종류 열거가 아직 없다** — `crew.tsv` 에 열 하나(`trait`)를 끝에 붙인다.

### 14-3. 타순이 만드는 판 (예)

```
판을 읽는 순서 →  [표식 Lv1] [고무 Lv2] [강타 Lv3 궁극기] [연타 Lv1] [지속 Lv2]
피해              +30%      다음 ×3    궁극기 ×3 ×1.3     잡몹 정리   다음 교환에도
```
같은 다섯 블록을 거꾸로 두면 궁극기가 맨 처음 맨몸으로 나가고 고무는 연타에 걸린다. **같은 판, 같은 하트, 피해는 몇 배 차이.** 이것이 유저가 "정리" 에서 고민하는 것이고, 운빨존많겜의 "기절 3개를 어디에 세우나" 와 같은 무게다.

### 14-4. 읽힘 점검

* 판에 보이는 것: 얼굴 + Lv 색 + **특성 아이콘 하나**(표식·고무·강타·연타·빙결·지속). 여섯 아이콘은 외울 수 있다.
* 공격 버튼 위 **예상 피해 카운터**(§11 ③)가 타순을 반영해 바뀌므로, 블록을 옮길 때마다 숫자가 오르내린다. 규칙을 몰라도 "이쪽에 두니 숫자가 커진다" 로 배운다.
* 순서를 모르는 사람도 손해가 크지 않다: 특성 없이 쏴도 Lv 합은 그대로다. 순서는 상한을 올리는 것이지 하한을 깎는 것이 아니다.

## 15. v3.1 안 — 런 시작 슬롯이 "계열 3개" 를 정한다 (2026-11-08, 사용자 제안)

> §10-2 의 "N=5 고정" 을 바꾼다. 한 런의 심볼은 **3계열**이고, 그 셋은 **런 시작 때 슬롯이 정한다.** 매 런 다른 셋이 나오므로 적어도 빤하지 않고, 한 런 안에서는 셋뿐이라 합성이 막히지 않는다.
> "너무 많으면 합성이 안 되고 너무 적으면 빤하다" 를 **한 판 안은 적게, 판과 판 사이는 많게** 로 푼다. 운빨존많겜이 "등급 하나 안은 5종, 전체는 수십 종" 으로 푼 것과 같은 꼴이다.

### 15-1. 시작 슬롯

```
  ┌──────┬──────┬──────┐
  │ 세바 │  검  │ 엘사 │   ← 3릴이 멈추면 이번 런의 계열 셋
  └──────┴──────┴──────┘
   내가 고름   운     운
```

* **릴 1 은 내가 고른다** (편성에서 한 명, 또는 장비 한 종). 릴 2·3 은 **보유 풀에서 무작위**. 전부 운이면 "내 전략" 이 없고, 전부 선택이면 매 런이 같다.
* 풀 = 보유 동료 64명 + 장비 계열 3(검·갑옷·목걸이). 장비는 §10-3 의 3칸 그대로다.
* 로딩 화면에 정적으로 보여 주는 것보다 **슬롯 연출**이 낫다. 룰렛이 이 게임의 얼굴이고, 여기가 첫 "①릴 매치" 순간이다. 멈춘 뒤 **"이번 판 최대 피해 ×N"** 을 같이 띄운다 — 이 셋으로 끝까지 합치면 어디까지 가는지(15-3).
* 리롤: 하트 1 또는 광고 1회. 운빨존많겜의 "모집 재시도 5회" 자리.

### 15-2. 레벨 4까지, 크기 1·2·4·8

30장을 3계열로 나누면 계열당 10장이다. 3단에서 멈추면 Lv3 둘 + Lv2 하나로 금방 차서 합성이 "작업" 이 된다(§10-2 의 N=3 평가). **그래서 한 단을 더 연다.**

| 레벨 | 크기 | 장수 | 동료 블록이 쏘는 것 | 장비 블록이 하는 것 |
| :---: | :---: | :---: | :--- | :--- |
| Lv1 | 1×1 | 1 | `SKILL1` 100% | 검: 히어로 평타 ×1 · 목걸이: 하트 +1 · 갑옷: 목숨 보호 1회 |
| Lv2 | 1×2 | 2 | `SKILL2` 300% | ×3 / 하트 +3 / 보호 1회 + 적 공격 절반 |
| Lv3 | 2×2 | 4 | `SKILL3` 궁극기·소환 | 히어로 궁극기 ×1 / 룰렛 +1 / 적 턴 1회 삭제 |
| **Lv4** | **2×4** | **8** | **각성**: `SKILL3` ×3, 화면 전체 컷인 | 히어로 궁극기 ×3 / 룰렛 +3 / 적 턴 2회 삭제 |

* 계열당 10장 = **Lv4(8) + Lv2(2)**. 셋이면 24 + 6 = 30칸. **6×6(36) 에 여유 6** — §1-1 이 그대로 맞는다. 5×5 는 역시 안 된다.
* Lv4 는 새 스킬 데이터가 아니라 **3단 ×3 + 연출**이다. 열거를 늘리지 않는다.
* 장비 블록도 **쏜다**(히어로의 행동이다). 그래서 릴이 장비 셋을 뽑아도 런이 성립한다 — 히어로 혼자 치는 런. 지금 코드에도 "CREW 가 없으면 히어로가 바로 공격" 이 있다.
* 2×4 블록은 판에서 **눈에 띄게 크다.** 이것이 "한방" 의 그림이다. 세로 판에서 가로 2×세로 4 로 세운다.

### 15-3. "이번 판 최대" 가 보이는 이유

계열 셋이 정해지면 상한이 계산된다: 각 계열 Lv4 하나 + Lv2 하나, 특성(§14)과 타순 최적. 이 수를 시작 슬롯 아래에 **"최대 ×N"** 으로 적는다.
* 적 체력과 나란히 보이므로 "이 셋으로 보스가 되나" 를 **시작 전에** 안다. 안 되면 리롤하거나 목숨을 쓸 각오를 한다.
* 운빨존많겜의 "원하는 유닛 못 뽑으면 GG" 불만을 **시작 10초 안에** 드러내고 리롤로 풀어 준다. 20분 뒤에 알게 하지 않는다.

### 15-4. §10-2 와의 관계

| | v3 (§10-2) | v3.1 (§15) |
| :--- | :--- | :--- |
| 한 런의 심볼 | 5 (내가 고른 동료 5) | **3** (내가 1 + 운 2, 동료·장비 섞임) |
| 레벨 | 3 | **4** |
| 계열당 장수 | 6 → Lv3+Lv2 | 10 → **Lv4+Lv2** |
| 한 스핀에 짝 | 52% | 78% |
| 런마다 다른 것 | 내 선택 | 슬롯 결과 (+내 선택 1) |
| 장비의 자리 | 판 밖 3칸 | 판 밖 3칸은 그대로 + **계열로 뽑히면 판 위 블록** |

**v3.1 로 간다.** 이유: (1) §10-2 의 "장비를 판에 올리나" 논쟁이 사라진다 — 뽑히면 올라간다. (2) 런마다 조합이 달라 LBaL 식 변주가 생기되 판 안은 셋이라 읽힌다. (3) 2×4 Lv4 가 한방의 그림을 만든다.

### 15-5. 가정

1. 계열 3, 레벨 4, 크기 1·2·4·8, 판 6×6, 룰렛 10회.
2. 릴 1 선택 + 릴 2·3 무작위. 리롤은 하트 1 또는 광고.
3. 장비 블록은 히어로의 행동으로 쏜다. 장비 셋짜리 런도 성립한다.
4. Lv4 = 3단 ×3. 데이터 추가 없음.

## 17. CS 연결 및 대화에서 확정한 수정 (2026-11-09)

**후속 정정:** 성은 계정이 보유한 기존 CS 성과 대포를 그대로 표시한다. 합성 모드 때문에 대포를 숨기거나 전투 웨이브 진행도에 따라 성 외형을 바꾸지 않는다. 그리드는 성벽 실루엣을 없애고 빈틈 없는 직사각형 4행으로 바꾼다. 기존 용량을 4칸 단위로 올림해 성별 24, 28, 32, 32, 36, 40, 44, 44, 48, 48칸을 사용한다. RH의 원본 `slot.png`(512×218)는 동일 비율 320×136으로 줄이고 위아래 이웃 심볼은 표시하지 않는다. 심볼은 릴 창 안에만 그린 뒤 원본 금색 테두리를 마지막에 덮는다. 오른쪽 레버를 당기거나 더 돌리기를 누르면 같은 하트 -1 뽑기를 실행한다. **전투 시작**은 항상 새 런을 만들고 최초 3개 추첨·비행·안착을 보여 준다. 기존 런은 별도의 **이어서** 버튼으로만 복구한다.

**화면과 판 크기에 대한 최신 요청:** 하단 정렬을 사용한다. 1:1.33(640×850)에서 성의 하단·바퀴·데크와 동료가 보이도록 기준선을 잡고, 더 긴 화면의 추가 높이는 성과 배경을 보여 주는 데만 사용한다. 인벤토리·슬롯·하트·버튼은 화면 높이에 따라 늘리거나 위로 이동하지 않는다. 고정 6×6 규칙은 기존 성별 가방 배치로 대체한다. `CastleData.cpp`의 동일한 칸 표와 `grid0.png`~`grid9.png`를 사용하며, 1~10성의 유효 칸 수는 **24, 26, 29, 32, 35, 38, 41, 44, 46, 48**이다. 그리드 이미지는 기존 생성기를 통해 남색 바탕·얇은 픽셀 테두리로 수정하며 성별 실루엣을 보존한다. 배치·합성·자동 배치·발사 순서도 이 마스크를 따른다. 세이브 v4에는 그리드 모양을 함께 기록한다. 기존 v3 판은 손실 없이 재배치할 수 있을 때만 성 모양으로 옮기며, 칸이 모자라거나 공격 중이면 기존 판을 유지한 뒤 교환 종료 시 적용한다.

**시작 연출에 대한 최신 요청이 §15·§16의 첫 릴 선택/리롤보다 우선한다.** 전투 시작을 누르면 보유 동료와 장비 3계열의 풀에서 서로 다른 계열 3개를 모두 무작위로 정한다. 각 계열 Lv1 블록 하나씩을 무료로 지급한다. 시작 보상은 하트나 적립 횟수를 쓰지 않는다. 전체 화면에 반투명 막을 올리고 확대 슬롯을 돌려 세 릴을 순차 정지시킨다. 결과 3개는 인벤토리의 실제 배치 칸으로 차례로 날아가 안착·점멸하고, 막과 슬롯이 페이드 아웃한 다음 전투 조작을 연다. 연출 중 배치·돌리기·공격·나가기 입력은 차단한다. 시작 결과와 판은 연출 전에 한 번 저장하며, 저장 복구에서는 이미 지급된 시작 보상을 다시 지급하지 않는다.

현재 구현은 `feature/merge-roulette`의 로비 **룰렛 합성 전투** 버튼으로 들어간다.
TURNRPG로 설정한 상태의 기존 전투 입장도 같은 화면으로 연결한다.

- **베팅은 삭제한다.** 더 돌리기와 지금 공격 모두 하트 **1개**를 쓴다. 피해 배수 선택은 없다.
- 슬롯의 `n/10` 숫자 표시는 삭제한다. 내부 적립 한도 10회는 유지하며, 소진 시 돌리기가 잠긴다.
- 인벤토리는 §16의 **6×6**이다. 동료와 검·갑옷·목걸이가 시작 슬롯의 세 계열을 구성한다.
- 하트는 슬롯 아래에 개별 픽셀 아이콘으로 표시한다. 사용한 자리는 회색으로 남긴다. `MergeRouletteSetHeartCapacity(5..20)`로 표시 칸 수를 바꿀 수 있고, 10개를 넘으면 두 줄이다. 계정 하트 잔액 자체를 잘라 버리지는 않는다.
- 상단 공용 HP HUD는 없다. 히어로 발밑에는 §16의 목숨, 적 발밑에는 체력 수치와 바를 표시한다. 방어력은 §10-4대로 쓰지 않는다.
- 배경·선로·이동성·바퀴·데크는 CS의 기존 렌더러와 앵커를 사용한다. 슬롯은 기존 `slot.png`의 3릴 영역이다. 블록 아이콘도 실제 동료·장비 리소스다.

### 코드와 저장

`BoardModel.h`와 `Def/BoardDef.h`의 크기·자리 판정·끝에서 안쪽 당김·릴 족보·타순·특성 수치를 재사용한다.
`MergeRouletteModel.h`는 그 위의 런 상태, RNG, 트레이 드래그/자동 배치, 공격 큐, 지속·소환·다음 교환, 웨이브 진행 및 검증 가능한 직렬화를 맡는다.
`Func_MergeRoulette.cpp`가 기존 리소스, 입력, 하트·골드·장비 보상과 연결한다. ACTIONRPG의 Play/GridTest 루프와 동시에 실행하지 않는다.

세이브는 `ROBINDATA` 끝의 `mergeRouletteRun` 및 `mergeRouletteHero`다. 기존 `player_flag`의 **kind 9**로 버전이 붙은 ASCII 바이트를 왕복한다. 인벤토리·계열·트레이·잔여 룰렛·목숨·지속 효과뿐 아니라 공격 중 큐와 이미 적용한 타격도 저장한다. 하트 차감 및 처치 보상과 같은 revision 스냅샷에 들어가며, 옛 세이브의 kind 9 누락은 새 런으로 처리한다. 새 DB 테이블이나 운영 DB 변경은 필요 없다.

동료 특성은 CS의 `AllyBalanceData.h`에 이미 있는 Action을 여섯 특성으로 접는다. 같은 동료의 특성 표를 `crew.tsv`에 중복해서 만들지 않는다. 광고·패스·결제의 상품 연결은 기존 서비스 계층의 후속 작업이며, 이번 전투 화면은 하트 리롤 경로를 제공한다.

### 확인 방법

1. `cmd /c tools\merge_roulette\test_model.cmd`: 합성 실패 시 보존, 경계 배치, 릴 한도, 타순·예상 피해, 장비 효과, 공격 중 저장 복구, 무작위 5,000회 배치 검사.
2. `python tools/board/test_board_model.py`: 기존 판 모델 회귀 검사.
3. Win32 Debug 빌드 후 `python tools/merge_roulette/verify_runtime.py`: 640×850 및 640×1408에서 실제 입력 경로로 계열 뽑기·하트 차감·배치·공격·재충전을 검사하고 단계별 PNG를 `output/merge-roulette/<높이>/`에 남긴다. 리뷰는 격리 저장소를 쓰며 계정 로그인 및 저장을 실행하지 않는다.
4. `CS_CASTLE_PROTOCOL_TEST=1`로 실행하면 성 진행도와 합성 런의 실제 덤프 인코더/디코더 왕복을 계정 I/O 없이 검사한다.

### 첨부 시안 기준 화면 구성

2026-11-09 사용자가 다시 첨부한 노을 배경 시안을 화면 구성의 기준으로 삼는다. 640×850에서 상단 전투 약 200px, 중앙 인벤토리 폭 약 288px, 금색 3릴 슬롯 452×184px, 하트 바 376×66px, 하단 선택 버튼 각각 264×94px로 배치한다. 640×1408에서는 하단 조작부 비율을 유지하고 인벤토리와 전투 공간을 확장한다. 판의 논리 크기 6×6과 합성 규칙은 유지하고, 직사각형 셀의 가로·세로 좌표를 따로 계산해 드래그에 적용한다.

빈칸은 남색 바탕과 꺾인 청색 테두리, Lv1은 회색, Lv2 동료는 파랑·장비는 초록, Lv3은 빨강, Lv4는 금색이다. 블록에는 실제 리소스와 하단 레벨만 표시한다. 하단은 금색 테두리의 파랑 ‘더 돌리기’와 빨강 ‘지금 공격’, 순환 화살표·쌍검 아이콘, 각각의 하트 -1 및 가운데 OR로 구성한다. 사용한 하트는 같은 위치의 회색 윤곽으로 남는다. 노을 지역 배경과 기존 성 리소스를 사용하며 합성 모드의 첫 성에서는 데크의 대포를 숨겨 히어로와 동료가 드러나게 한다. 전투 수치판은 각 전투원 아래에 놓는다. 목숨 규칙은 유지하며 아군 수치판의 방어 표시는 갑옷 등급으로 추가된 목숨 수, 적은 기존 규칙대로 방어 0을 표시한다.

## 18. 3단으로 되돌리고 트리에 등급을 둔다 (2026-11-09)

* **합성은 3단이 끝이다.** 왕가 = 궁정 재상 → 왕실 공주 → 국왕처럼 세 인물이면 이야기가 선다. 넷째 칸을 억지로 채우면 "각성" 같은 설명이 필요해진다. v3.1 §15-2 의 Lv4 는 폐지.
* **트리의 등급 = Lv1 의 성급.** 재상(★4)에서 시작하는 왕가 트리는 릴 2·3 에 드물게 나온다(가중치 ★1 트리 4 · ★2 트리 2 · ★3 이상 1). 흔한 트리는 ★1 → ★3 → ★4, 드문 트리는 ★4 → ★4 → ★6. 뽑힌 트리가 곧 그 판의 운이다. 운빨존많겜에서 "같은 등급 안 5종 + 신화 레시피" 가 하던 일을 **트리 20개의 등급**이 한다.
* 숫자: 계열당 10장 = Lv3 둘 + Lv2 하나 = 10칸. 셋이면 30칸, 36칸 판 그대로.
* 코드: `BLOCK_LV_MAX 3`, `BoardModel.h` 의 Lv4 표 삭제, `content/merge_tree.tsv` 에 `weight` 열. Codex 의 `MergeRouletteModel.h` 는 `MaxLevel = BLOCK_LV_MAX` 라 따라오지만 `p.damage[3]`(Lv4 값) 같은 자리는 정리가 필요하다.

### 운빨존많겜의 뽑기와 고급 유닛 (질문에 대한 답)

* 운빨존많겜에는 **판 안에 고급 유닛을 꽂아 주는 뽑기가 없다.** 판 밖 "영웅 모집" (초대장, 최대 5회·무료 4회) 은 유닛 **카드** 를 주고, 카드는 그 유닛의 **영구 레벨** 재료다. 중복이 나와도 판에 유닛이 생기지 않고 레벨 재료가 된다.
* 신화 유닛은 3,000 다이아로 "명함" 을 사거나 공용 재료 **신화석** 으로 해금·6레벨까지 강화한다. 보유 신화가 중복으로 나오면 **신화석 300** 으로 바뀐다. 신화석은 판 안 도박(행운석)과 사냥패스로 쌓인다.
* 즉 뽑기는 **"그 유닛이 내 판에 나올 수 있게 + 나왔을 때 더 세게"** 만 한다. 판에 **등장시키는 것은 언제나 판 안의 소환·합성·레시피**다.
* 우리도 같은 선을 긋는다. 동료 가챠는 **(1) 그 동료가 속한 트리를 릴 풀에 넣고 (2) 중복은 성급 승급 재료**다. 트리를 다 모아야 그 트리가 릴에 뜬다 — 왕가 트리는 재상·공주·국왕 셋을 가져야 열린다. 판 안에 국왕을 꽂아 주는 상품은 없다.

### 운빨존많겜: 미보유 유닛·프리셋·고급 유닛 확률 (2026-11-09 추가 조사)

* **판에는 해금한 유닛만 나온다.** 영문 가이드 원문: "In each match, you summon warriors you have unlocked, with no specific pattern." 신화는 레시피 재료가 다 서 있어도 **명함(해금)이 없으면 못 만든다**. 불멸은 신화를 15레벨까지 키워야 해금된다(공식 헬프센터).
* **프리셋(덱)은 없다.** 소환 풀은 "해금한 전부". 다만 판 안에서 신화 탭에서 목표 신화를 고르면 "필요한 유닛을 필드에 표시" 해 준다 — 목표 선택 UI 이지 덱이 아니다. 즉 센 유닛을 "세팅해서 나오게" 하는 길은 없고, 세게 **만들 수 있게**(해금·레벨) 하는 길만 있다.
* **확률.** 공개된 확정 수치는 행운석 도박(희귀 60% · 영웅 20% · 전설 10%)과 유물 보정(영웅 +5%, 전설 +3%)뿐이다. 일반 소환의 등급별 기본 확률과 행운 업그레이드 단계표는 공식 공개 자료를 찾지 못했다. 클론 구현(jwdev1995)이 쓴 68 / 24 / 7 / 1 % 가 통용되는 어림값이고, 행운을 올리면 희귀·영웅 쪽으로 기운다. 2024년 확률 편향 사고 뒤 111% 가 소스와 서버 로그를 공개한 전례가 있다(인벤).
* **우리와의 대응.** 해금 = 트리 3명을 다 가짐. 풀 = 해금한 트리 전부(릴 2·3). 운빨존많겜에 없는 **"릴 1 선택"** 을 일부러 둔다 — 그쪽은 협동 상대가 변수를 주지만 우리는 혼자라 선택 하나가 있어야 전략이 생긴다. 고급 트리 확률은 가중치 ★1 4 · ★2 2 · ★3+ 1 로 시작하고 플레이로 고친다.
