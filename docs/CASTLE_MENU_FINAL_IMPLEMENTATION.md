# 성 메뉴 최종 개편

## 적용 기준

작업 시점에 `CASTLE_SURVIVOR_CASTLE_MENU_FINAL_CODEX_SPEC.md`가 저장소 및 다운로드 폴더에 없었다. 이번 사용자 메시지의 요구사항을 기준으로 구현했으며 원문 전용 세부 규칙은 추후 대조가 필요하다.

## 화면과 데이터

- 고정 헤더 아래 성 선택, 조립 미리보기, 능력치 요약, 출정/구매, 업그레이드 목록이 하나의 세로 스크롤 영역이다. 작은 화면에서도 콘텐츠를 축소하지 않는다. 하단 로비 메뉴가 콘텐츠나 터치를 덮지 않는다.
- 표시 순서는 첨탑, 대포, 외부장갑, 실내, 바퀴다. 기존 저장 인덱스는 각각 `0, 3, 1, 2, 4`로 유지한다.
- `CastleMenuModel::Upgrade(..., false, gold)`의 기존 골드 비용과 최대 Lv.5를 사용한다. 미보유/골드 부족/최대 레벨에서 구매를 차단한다. 유료 재화나 새 가격을 추가하지 않는다.
- 실내는 기존 `parts[c][2]`다. 창고·무기고·병영·공방·지휘실의 별도 `rooms` 업그레이드 UI 및 층 미리보기는 노출하지 않는다. 기존 `rooms` 저장값과 그 효과는 삭제하거나 초기화하지 않는다.
- 미리보기는 실제 `CastleParts` 조립 경로의 `DrawIndividualCastle`을 사용한다. 실제 rig 폭·높이로 맞추는 메뉴용 진입점을 추가했다. 대포도 같은 mounted cannon 데이터를 사용한다. 새 성 이미지를 만들지 않는다.
- 파츠 썸네일은 기존 성 리소스의 첨탑/외벽 영역, 대포 아틀라스, 실내 리소스, 실제 바퀴 리소스에서 가져온다.
- 업그레이드 시 기존 `CastleSaveChanges` → `RefreshStat` → `SaveGame`을 호출한다. `CastleVisualPartLevel`의 레벨과 선택 성의 `gMobileCastleVisual`을 갱신한다. 성 구매/출정 변경의 기존 용량 검사도 유지한다.
- 조립 이미지의 외형 변화 범위는 기존 렌더러 정책을 따른다. 현재 individual 성 본체와 바퀴는 기존 고정 아트를 사용하며, 메뉴 개편에서 단계별 외형을 새로 만들거나 교체하지 않는다. 대포와 실내는 기존 단계별 리소스를 사용한다.

## 검증

`tools/castles/verify_castle_final.ps1`은 640×850, 640×960, 640×1136, 640×1408에서 실제 실행한다. `output/castle-final-높이/`에 상단, 하단, 업그레이드 후, 구매 확인, 두 번째 성, 열 번째 성 화면과 로그를 남긴다.

검사 내용은 10개 성 × 5개 파츠의 Lv.0~5 비용/골드 부족/최대 레벨, 실제 파츠 업그레이드 명령, 골드 차감과 유료 재화 유지, 기존 실내 방 데이터 유지, 코스튬 레벨 조회 갱신, 전체 콘텐츠 스크롤 끝, 등록된 버튼 터치, 골드 성 구매 및 출정 성/코스튬 변경, 메뉴 종료다.
